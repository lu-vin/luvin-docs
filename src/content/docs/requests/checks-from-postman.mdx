When you import a collection, its tests keep working. Postman tests and Bruno scripts come over whole, to the **Scripts** tab, and run as in the original once you trust the collection. Bruno's `vars:post-response` and `assert` blocks, which have no code, become the **Variables** and **Checks** tabs of each request.

This page lists what becomes a check, and how to turn a script test into a check by hand if you prefer checks without code.

## Where each part goes

| From | Goes to |
|---|---|
| Postman: the **Pre-request** script of the collection, a folder or a request | The **Before request** script of the same level |
| Postman: the **Tests** (post-response) script of the collection, a folder or a request | The **After response** script of the same level |
| Bruno: `script:pre-request` of `collection.bru`, `folder.bru` or a request | The **Before request** script of the same level |
| Bruno: `script:post-response` and `tests` | The **After response** script of the same level, the first one and then the other |
| Bruno: `vars:post-response` of a request | The **Variables** tab of the request |
| Bruno: `assert` of a request | The **Checks** tab of the request |

This works from a folder of `.bru` files and from the `.json` Bruno exports. See [Scripts](/requests/scripts/) and [Import from Postman or Bruno](/get-started/import/#scripts-come-over-whole).

## Bruno blocks that become variables and checks

```
vars:post-response {
  token: res.body.token
}
assert {
  res.status: eq 200
  res.body.name: isString
  res.body.types: isNotEmpty
  ~res.body.order: gt 0
}
```

After the import, the request has:

| Tab | Row |
|---|---|
| **Variables** | `token` ← `res.body.token` |
| **Checks** | `res.status` **equals** `200` |
| **Checks** | `res.body.name` **is text** |
| **Checks** | `res.body.types` **is not empty** |
| **Checks** | `res.body.order` **is greater than** `0`, unticked (it was turned off in Bruno with `~`) |

The operator of each `assert` line must be one of the [names in the file](/requests/check-operators/#all-the-checks) of Luvin, which are the same as Bruno's. A line with an operator Luvin does not have, such as `between`, is skipped.

The left side must be something Luvin can read from the response:

| In Bruno | In Luvin |
|---|---|
| `res.body.id`, `res.getBody().id`, `res("id")` | `res.body.id` |
| `res.body.items[0].id` | `res.body.items[0].id` |
| `res.status`, `res.getStatus()` | `res.status` |
| `res.responseTime`, `res.getResponseTime()` | `res.responseTime` |
| `res.getHeader("X-Id")`, `res.headers["X-Id"]` | `res.headers.x-id` |

### What the summary says

Before you import, the summary of the collection says *3 Bruno variable(s) and assertion(s) went to the Variables and Checks tabs of each request.* If a line was skipped, it warns: *Some Bruno assertions or response variables could not become Checks or Variables.* Write those lines by hand in the **Checks** tab, or as a test in the **After response** script.

## Turn a script test into a check

A test in a script and a check in the **Checks** tab can say the same thing. Checks need no code, are easier to review and show next to the status. To move a test to the **Checks** tab, use these equivalences, and then delete the test from the script.

```js
const jsonData = pm.response.json();
pm.test("It is Pikachu", function () {
  pm.response.to.have.status(200);
  pm.expect(jsonData.name).to.eql("pikachu");
  pm.expect(jsonData.types).to.be.an("array");
  pm.expect(pm.response.responseTime).to.be.below(1000);
});
```

is the same as these checks:

| From the response | Check | Expected value |
|---|---|---|
| `res.status` | **equals** | `200` |
| `res.body.name` | **equals** | `pikachu` |
| `res.body.types` | **is a list** | |
| `res.responseTime` | **is less than** | `1000` |

### What the script reads

| In the script | From the response |
|---|---|
| `pm.response.json().id`, `jsonData.id` (after `const jsonData = pm.response.json()`) | `res.body.id` |
| `pm.response.code` | `res.status` |
| `pm.response.responseTime` | `res.responseTime` |
| `pm.response.headers.get("X-Id")` | `res.headers.x-id` (header names in lower case) |

### The chain

| Chain | Check |
|---|---|
| `pm.response.to.have.status(201)` | `res.status` **equals** `201` |
| `pm.response.to.be.ok`, `pm.response.to.be.success` | `res.status` **is at least** `200` and **is less than** `300` |
| `pm.response.to.have.header("X-Id")` | `res.headers.x-id` **exists** |
| `.to.eql(x)`, `.to.equal(x)` | **equals** |
| `.to.not.eql(x)` | **does not equal** |
| `.to.be.above(x)`, `.to.be.at.least(x)` | **is greater than**, **is at least** |
| `.to.be.below(x)`, `.to.be.at.most(x)` | **is less than**, **is at most** |
| `.to.include(x)`, `.to.not.include(x)` | **contains**, **does not contain** |
| `.to.match(/…/)` | **matches (regex)** |
| `.to.exist`, `.to.not.exist` | **exists**, **does not exist** |
| `.to.be.null`, `.to.be.empty`, `.to.not.be.empty` | **is null**, **is empty**, **is not empty** |
| `.to.be.ok` | **is truthy** |
| `.to.be.a("string")`, `"number"`, `"boolean"`, `"array"`, `"object"` | **is text**, **is a number**, **is true/false**, **is a list**, **is an object** |
| `pm.expect(jsonData).to.have.property("id")` | `res.body.id` **exists** |
| `pm.expect(jsonData.items).to.have.lengthOf(3)` | `res.body.items.length` **equals** `3` |
| `pm.expect(jsonData.id).to.eql(pm.environment.get("orderId"))` | `res.body.id` **equals** `{{orderId}}` |

### What to keep as a script

Keep it in the script when the test:

- only makes sense under a condition, such as `if (pm.response.code === 404)`;
- loops over a list, such as every item of `jsonData.items`;
- computes the expected value, such as a sum or a date;
- saves a value that must stay after closing Luvin (`pm.environment.set`). The **Variables** tab keeps values only while the collection is open.
