A request is one API call saved on its own, outside a workflow. Use it to try an endpoint, to look closely at a step that fails, or to keep a call you repeat often.

<video controls muted playsinline preload="metadata" poster="/media/en/request-from-curl.webp" src="/media/en/request-from-curl.mp4"></video>

## A request in one look

You write a method and a URL, press **Send** and read the answer:

```text
GET https://jsonplaceholder.typicode.com/posts/1   →   200 OK
```

```json
{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident occaecati excepturi optio reprehenderit",
  "body": "quia et suscipit\nsuscipit recusandae consequuntur expedita et cum\nreprehenderit molestiae ut ut quas totam\nnostrum rerum est autem sunt rem eveniet architecto"
}
```

Luvin saves it as this file, so it is there next time:

```yaml title="requests/get-post.request.yaml"
name: Get post
kind: http
method: GET
url: https://jsonplaceholder.typicode.com/posts/1
headers:
  - key: Accept
    value: application/json
auth:
  type: inherit
```

Try it yourself in [HTTP requests](/requests/http/).

## Request or workflow

| You want to | Use |
|---|---|
| Call one endpoint and read what it answers | A request |
| Call several endpoints in order, passing data from one to the next | A [workflow](/design/overview/) |
| Get test cases and a verdict for each one | A workflow |

A request has no cases and no verdict: you send it and read the response.

## Create a request

<Steps>

1. In the sidebar, open your collection and click **New request** (the row with a **+** under the collection). You can also use the **+** at the end of the tabs (**Create or import**) and choose **New request**.
2. The **New request** dialog opens. Choose a kind.
3. The request opens in its own tab, ready to fill in.

</Steps>

| Option | What it creates |
|---|---|
| **HTTP** | A REST call: GET, POST, PUT, PATCH, DELETE, HEAD or OPTIONS. |
| **GraphQL** | A query or mutation with variables. See [GraphQL](/requests/graphql/). |
| **gRPC** | A call to a method of a `.proto`. See [gRPC](/requests/grpc/). |
| **WebSocket** | A live connection to send and receive messages. See [WebSocket](/requests/websocket/). |
| **Workflow (Arazzo)** | Not a request: an empty workflow, opened in **Design**. |
| **Import from cURL** | An HTTP request built from a pasted command. See [cURL](/requests/curl/). |

## The request screen

![A single request with its method, URL, tabs and the response below](/media/en/request.webp)

From top to bottom:

- **Name.** Click it to rename the request. To its right you see the save state. The active environment is at the top right of the window.
- **Method, URL and Send.** Choose the method, write the URL and press **Send** (⌘/Ctrl + Enter). While the request is on its way, the button becomes **Cancel**.
- **Request tabs.** **Params**, **Authorization**, **Headers**, **Body**, **Variables**, **Checks** and **Scripts**. On the right of the tabs, **Variables in request** opens the Variables panel on the variables this request uses (see [Params, headers and body](/requests/params-headers-body/#variables-in-request)), **Cookies** opens the cookie jar and **Copy as cURL** shows the request as a terminal command.
- **Response.** The status, the time and the size, then the tabs **Body**, **Headers**, **Cookies** and **Sent request**, plus **Checks** when the request has checks or saves variables, and **Tests** and **Console** when [scripts](/requests/scripts/) ran. **Sent request** shows what Luvin really sent: the final URL, every header and the body. See [Variables and checks](/requests/variables-and-checks/).

In the **Body** tab of the response, **Pretty** formats and colours the answer, **Raw** shows it exactly as the server sent it, and **Preview** shows JSON as a table you can expand or renders an HTML page.

Drag the line between the request and the response to resize them, as in Postman. The body and script editors grow to fill the space. Double-click the line to go back to the original size. You can also click it and use ↑ and ↓. Luvin remembers the size on this computer, for every request.

:::note
If the request cannot be completed, the response area says **The request couldn’t complete** and gives the reason. See [Connection help](/dev-tools/connection-help/).
:::

## Saving

Luvin saves every change on its own. The request header shows **Saved automatically**; ⌘S (Ctrl+S) saves right away.

In a workspace, each request is a YAML file inside the collection folder, under `requests/` (the file above). Secrets typed in the **Authorization** tab are never written to it. See [How a request is saved](/requests/files/) and [Authorization](/authorization/overview/).

Without a workspace the header says **Not saved**: open or create a workspace to keep your changes.

## Authorization

The **Authorization** tab sets how Luvin identifies itself to the API: an API key, Basic Auth, a Bearer token, OAuth 2.0 and more. A request can have its own, or inherit the one of the collection. See the [authorization overview](/authorization/overview/).

## Folders

Folders are real subfolders of `requests/`, so they look the same on disk and in git.

<Steps>

1. Open the **⋯** menu of the collection, of the **REQUESTS** section or of another folder.
2. Choose **New folder**. The folder appears with its name ready to type.
3. Type the name and press Enter.

</Steps>

| To | Do this |
|---|---|
| Move a request | Drag it onto a folder, or open its **⋯** menu and choose **Move to “folder”**. **Move out of the folder** takes it back to the top level. |
| Copy or move a request or a folder to another collection | **⋯** → **Copy to another collection** or **Move to another collection**, or drag it onto the other collection. See [Copy or move to another collection](/workspaces/move-between-collections/). |
| Rename a folder | **⋯** → **Rename**. |
| Delete a folder | **⋯** → **Delete**. Luvin asks first, because the requests inside are deleted too. |

## Rename, duplicate or delete a request

Open the **⋯** menu of the request in the sidebar:

- **Rename** changes the name and the file name. Editing the name at the top of the request screen does the same.
- **Duplicate** creates “name (copy)” in the same folder and opens it.
- **Delete** asks for confirmation and removes the file.

## Use a request as a workflow step

In the **Design** tab of a workflow, click **＋ Step** (or press `/`). The **Add a step** dialog opens: search for the request and choose it. You can also drag a request from the collection tree onto the canvas. Either way it becomes a step, sent exactly like the request. Only HTTP requests with a URL can become steps. See [Workflows from requests](/design/from-requests/).
