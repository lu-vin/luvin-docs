A workflow file can name a contract by its web address instead of a file next to it. That is common when a team publishes its contracts on a server. Luvin can download such a contract, together with the files it references, and use it like any other. This page explains how, and what to keep in mind.

For references between files of your collection, see [References between files](/contracts/references/).

## Example: the PokéAPI contract from a URL

A workflow file points to a published copy of the PokéAPI contract:

<Tabs>
<TabItem label="Workflow file">

```yaml title="pokemon.arazzo.yaml" {3}
sourceDescriptions:
  - name: pokeapi
    url: https://example.com/specs/pokeapi.openapi.yaml
    type: openapi
```

</TabItem>
<TabItem label="Before">

```text title="Contracts"
✕ pokeapi   openapi   Attach  Download  ⋯
```

The workflows that use it show errors, starting with *The contract for source "pokeapi" (https://example.com/specs/pokeapi.openapi.yaml) is missing.*

</TabItem>
<TabItem label="After Download">

```text title="Contracts"
✓ pokeapi   openapi   +  ⋯
```

The contract opens as **Read-only**, and the steps find their operations.

</TabItem>
</Tabs>

If the collection already has a file called `pokeapi.openapi.yaml`, Luvin uses it and downloads nothing: only the file name of the address counts. See [How a workflow finds its file](/contracts/add/#how-a-workflow-finds-its-file).

## Download a contract

The **Download** button shows on a row that did not load, when its address starts with `http://` or `https://`.

<Steps>

1. Click **Download** on the row.
2. Luvin downloads the file from the address and loads it. The mark changes to ✓.
3. Open it from the list. It shows **Read-only**.

</Steps>

If the download fails, the row stays ✕ and its tooltip tells why:

| Message | What it means | What to do |
|---|---|---|
| *Could not download it (…). Download the file and attach it manually.* | The server did not answer, or the address is wrong. | Download the file with your browser and use **Attach**, or import it into the collection. |
| *Could not download: HTTP 404* (or another code) | The server answered with an error. | Check the address in the workflow file. A `401` or `403` means the server wants credentials: download the file yourself. |
| *Could not read as YAML or JSON:* and a reason, or *"pokeapi.openapi.yaml" does not look like an OpenAPI document.* | The address answered something that is not a contract of that kind, such as a web page. | Use the address of the raw file. |

### References of a downloaded contract

A downloaded contract may reference other files, such as `./schemas/pokemon.yaml`. Luvin looks for each missing file next to the contract, on the same server, and loads the ones it finds. It repeats this up to three times, in case the files it found reference more files.

The files it cannot find stay in the message *Files referenced with $ref are missing: …* on the row. Add them by hand: drag them onto Luvin or use **Import contract…**.

A server in the contract written as a path, such as `/api/v2`, is completed with the address the contract came from: `https://example.com/api/v2`. See [Servers and credentials](/contracts/servers-and-credentials/).

## Attach a file instead

**Attach** works on any row that did not load, with or without an address. It opens a file picker: choose the contract from your computer and Luvin links it to that row, whatever its file name.

The file must be of the kind the workflow file asks for. Otherwise the row says *"name" does not look like an OpenAPI document.* (or AsyncAPI).

In a workspace, when the `url` of the row is a path inside the collection, such as `./pokeapi.openapi.yaml`, Luvin saves the file you choose into the collection folder under that path. From then on it is an ordinary contract of the collection: it is still there when you open the collection again, and you can edit it. Outside a workspace, or when `url` is an address or a path outside the collection (`../…`), the file is only linked to the row, as **Read-only**, and is not saved with the collection.

## Read-only, and how to edit it

A downloaded contract, or an attached file that Luvin did not save in the collection, belongs to its address or to your computer, not to the collection, so it opens as **Read-only**:

- The text of a downloaded contract is Luvin's reading of the file. Comments and the original layout may not be there.
- An attached file shows its text as it was.

To change it, click **Make a local copy**. Luvin adds it to the collection as a file with the same name, and from then on it is an ordinary contract you can edit. See [Edit a contract](/contracts/edit/#make-a-local-copy).

## Keep it, or get a newer version

<Aside type="caution" title="Downloads are remembered, not saved in the collection">
A downloaded contract is not written to the collection folder. In a workspace, Luvin remembers on this computer which contracts you downloaded in each collection, and downloads them again when you open the collection. If that fails, for example without network, the row shows ✕ and Luvin tries again the next time. Outside a workspace, continuing a saved session downloads it again for you. An attached file that Luvin did not save in the collection is not remembered: attach it again.
</Aside>

| You want | Do |
|---|---|
| The contract to stay with the collection, also for your team | **Make a local copy**. The file goes into the collection folder, and into git if you use it. A download is remembered only on this computer. |
| Always the version published at the address | Keep it remote. Luvin downloads it again each time you open the collection. |
| A newer version after a local copy | Download the file and import it: a file with the same name replaces the copy. |

While a remote contract is loaded, the row has no **Download** button. Opening the collection again is how you take the version that is published now.
