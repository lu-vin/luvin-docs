You do not need a workflow to check an operation. Luvin lets you call one operation of a contract on its own, with the data you write, and shows whether the answer matches the contract. Use it to see that an API is up, to learn what it answers, or to prepare the data for a workflow.

There are two ways: **Try it out** in the Swagger UI preview of the contract, and **Try alone** on a step of a workflow.

## Example: call `getPokemon` on its own

With the PokéAPI contract and the `local` environment:

| You do | Luvin does |
|---|---|
| Expand `GET /pokemon/{idOrName}`, click **Try it out**, type `pikachu` in `idOrName` and click **Execute** | Sends `GET https://pokeapi.co/api/v2/pokemon/pikachu` with the server of the active environment |
| Read the response in Swagger UI | Shows the status `200` and the JSON body |
| Open **Dev Tools**, **Network** | Records the call: **Case** *Try it out*, **Step** `/api/v2/pokemon/pikachu`, labelled **Swagger UI** |

## Try it from the contract

<Steps>

1. Open an OpenAPI contract from the **Contracts** list.
2. In the preview on the right, click an operation to expand it.
3. Click **Try it out**, fill the parameters and the body, and click **Execute**.

</Steps>

Swagger UI shows the response below. Its buttons and texts are in English, as in Swagger UI everywhere.

What Luvin does for you:

- **The server comes from the active environment.** The base URL of the environment is the first one in **Servers**, labelled *“name” environment (Luvin)*. Change the active environment and the call goes to another server.
- **The credentials come from the environment too.** For the API key, bearer and basic schemes of the contract, Luvin fills Swagger UI's **Authorize** with the values you set in the environment, so you do not type them. See [Variables and secrets](/environments/variables-and-secrets/).
- **The call goes out from Luvin, not from the preview.** It uses the proxy and certificates of [Preferences → Network](/get-started/network/).
- **Secrets are hidden.** The cURL command that Swagger UI shows hides the values of the environment secrets with `••••`.

This call is always against the real API. Nothing is simulated here.

<Aside type="note" title="A contract that no workflow uses">
The server and the credentials of the environment are stored under the name a workflow file gives the contract. A contract with ○ in the list has no such name yet, so **Servers** lists only the servers of the contract, and **Authorize** starts empty. Add the contract to a workflow file to get them. See [Add a contract](/contracts/add/#a-contract-added-after-the-workflow-file).
</Aside>

## Try it from a step

If a step of a workflow calls the operation, you can test it without leaving the workflow. This works for OpenAPI operations; messaging steps have no **Try alone**.

<Steps>

1. Open the step in a workflow.
2. Click **▶ Try alone**. The tooltip says *Call this operation on its own, outside the workflow, with the active environment*.
3. A tab opens with the operation. At the top, choose **Real API** or **Simulated**, check the environment, and press **Send** (⌘/Ctrl + Enter).

</Steps>

The form lists the parameters by place (**Path parameters**, **Query**, **Headers**, **Cookies**) and the **Body**. Required parameters have a `*`. An operation with neither says *This operation has no parameters or body.*

### Where the values come from

The form starts from the contract, not from the step:

| Field | Starting value |
|---|---|
| A parameter | Its `example`, else the first of its `examples`, else the `example` or `default` of its schema. Empty if there is none. |
| The body | The `example` of the request body, else the first of its `examples`, else a body built from the schema. |

Values accept `{{variables}}` of the environment and generators such as `{{$randomEmail}}`. **Contract example** puts the example body back. If the body is not valid JSON when you press **Send**, you see *The body isn’t valid JSON:* and the reason.

Luvin remembers what you typed for each operation while the app is open, so you can switch tabs and come back.

### Messages before you send

| Message | What to do |
|---|---|
| *The environment has no URL for “name” and the contract defines no servers: set it in the environment or use simulation.* | Add the base URL to the environment, or choose **Simulated**. |
| *Credentials are missing in “env”: the API will probably answer 401.* | Click **Configure** and fill the credentials. |
| *The environment credentials are sent (names).* | Nothing: the credentials were found. |
| *No value (required): names. You can still send it to see what the API answers.* | Optional. You can send anyway. |

### The response

Under **Response** you see the status, the time and one of two verdicts: **Matches the contract**, or *N difference(s) from the contract*. Open the card to read the request, the response and each difference. See [Does the response match the contract?](/contracts/response-check/)

With **Simulated**, Luvin answers from the examples of the contract and sends nothing to the network. See [Examples, simulation and mocks](/contracts/examples/).

## Where the call shows up

Every call from **Try it out** and **Try alone** is recorded in **Dev Tools**, in the **Network** tab, with secrets masked.

| Where you tried it | In the Network row |
|---|---|
| **Try it out** in the contract | **Case**: *Try it out*. **Step**: the path of the URL that was called. The call is labelled **Swagger UI**. |
| **Try alone** in a step | **Case**: the method and the path, for example `GET /pokemon/{idOrName}`. **Step**: the `operationId` (or `request` when it has none). The call is labelled **Try operation**. |

Open the row to see the headers, the body and the response. See [Network](/dev-tools/network/).
