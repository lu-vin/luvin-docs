## The API does not answer

When cases get no response, a panel titled **Could not reach the API** opens in the results. It says how many cases got no response and from which address.

**The URL is wrong or the server is down.** The panel has a link for each address, **Open …**. If it does not load, the problem is not Luvin: check the base URL in the environment (click **Review environment**), that the server is running and that your computer can reach it (VPN, proxy, firewall). If the API needs a proxy or a client certificate, set them in [Preferences → Network](/get-started/network/).

### Other ways out

| Button or tip | What it does |
|---|---|
| **Try in simulation** | Runs the cases without calling the API |
| **Review environment** | Opens the environment, to check the URLs |
| The cURL tip | Copy a step as cURL and try it in your terminal, to see the raw error |

## The app will not open

The desktop installers are not signed yet, so macOS and Windows warn you the first time.

- **macOS.** Try to open the app once, then go to **System Settings → Privacy & Security**, find the message about Luvin under **Security** and click **Open Anyway**. You only do this once.
- **Windows.** Run the installer. In the warning, click **More info**, then **Run anyway**.

The installers have been tested on macOS. The Windows and Linux builds have not been tried on those systems yet. See [Install and open Luvin](/get-started/install/).

## A contract shows ✕

In the **Contracts** section of the sidebar, ✓ means a contract is loaded and ✕ means it is not. Hover over the row to read the reason. A contract can show ✕ for three reasons:

- **Its file is missing.** The Arazzo mentions the contract, but its file was never added.
- **It could not be read.** The tooltip shows the error.
- **Files it points to are missing.** The contract uses `$ref` to other files that were not added. The tooltip says **Files referenced with $ref are missing** and lists them.

To fix it:

<Steps>

1. In the sidebar, click **Attach** on the row and choose the contract file. For missing `$ref` files, add them to the collection as well. See [Bring your own files and requests](/get-started/import/).
2. If the contract came from a web address, click **Download** on the row instead.

</Steps>

The row turns ✓ when everything is loaded. Until then, the steps that use that contract cannot be run.

## Errors after deleting a contract

When you delete a contract that steps use, Luvin warns you first: those steps will have no contract until you attach another one. If you went ahead, the workflow shows errors. Its dot in the sidebar turns red and tells how many errors there are, and the **Overview** tab lists them.

<Steps>

1. In the **Contracts** section, find the contract. It stays in the list with a ✕, because the Arazzo still mentions it.
2. Click **Attach** and choose the file again, or the file of the contract that replaces it.

</Steps>

If you do not want those steps any more, delete them. A contract that has no file and that no step uses can be removed with **Remove contract…**.

## Secrets are missing on another computer

Secrets are never in the workspace files. The environment files only keep the names of the secrets. The values are stored encrypted on the computer where you typed them, using the operating system's keychain.

So when you copy a workspace to another computer, or clone it from git, its secrets have no value there.

<Steps>

1. Open the environment in the **Environments** panel of the sidebar, or choose **Configure environment…** at the top right of the window.
2. Type the value of each secret again.

</Steps>

Share the values with your team through a safe channel, not through the files.
