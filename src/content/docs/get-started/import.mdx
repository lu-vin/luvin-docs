You do not have to start from nothing. You can bring Arazzo files and contracts, collections from Postman or Bruno, and a command copied as cURL.

An Arazzo file describes a workflow. A contract is an OpenAPI or AsyncAPI file. A **collection** is a project folder inside a workspace. See the [glossary](/reference/glossary/).

## Example: a Postman collection

A small collection exported from Postman:

```json title="shop-api.postman_collection.json"
{
  "info": {
    "name": "Shop API",
    "schema": "https://schema.getpostman.com/json/collection/v2.1.0/collection.json"
  },
  "item": [
    {
      "name": "Customers",
      "item": [
        {
          "name": "Get customer",
          "request": {
            "method": "GET",
            "url": "{{baseUrl}}/customers/42",
            "header": [{ "key": "Accept", "value": "application/json" }]
          }
        }
      ]
    }
  ]
}
```

Import it with an environment file that defines `baseUrl`, and Luvin creates a collection called **Shop API**:

<FileTree>

- shop-api/
  - collection.yaml
  - requests/
    - customers/
      - _folder.request.yaml
      - get-customer.request.yaml
  - environments/
    - sandbox.yaml

</FileTree>

In the sidebar, **Customers** is a folder and **Get customer** a request that sends `GET {{baseUrl}}/customers/42`. The variables of the Postman environment arrive in a Luvin environment. See [What is on disk](/workspaces/files/).

![The Import collection dialog with a card for Luvin, one for Postman and one for Bruno](/media/en/import-postman.webp)

### Import it

You need a workspace open. If none is, Luvin says **Open or create a workspace to import.** See [Create and open a workspace](/workspaces/create-and-open/).

<Steps>

1. Click **+** in the tabs (**Create or import**), then **Import collection (Luvin, Postman or Bruno)**. The same action is in the ⋯ menu of **Collections** in the sidebar and on the workspace home under **Quick actions**.
2. Choose what to import:

   | Tool | What to choose |
   |---|---|
   | Luvin | **Choose .luvin.json**: a collection exported from Luvin. See [Export and import a collection](/workspaces/export-import/) |
   | Postman | **Choose .json files**: the exported collection (v2.0 or v2.1). Choose the environment files too, to bring their variables |
   | Bruno | **Choose folder**: the collection folder as Bruno keeps it in git (with `.bru` files). Or **Choose .json** for the file Bruno exports |

   You can also drop the files on the dialog. A Luvin file (`.luvin.json`) or a Postman or Bruno JSON (a collection, an environment or a Bruno export) dropped anywhere on the window opens this dialog too, even in a workspace with no open collection: the window says **Drop to import the collection (Luvin, Postman or Bruno)**. Other files in the same drop go to the collection.
3. Read the summary. For each collection it shows the number of requests, folders, examples and environments, the collection authorization if there is one, and how many scripts come with it.
4. Change the collection name if you want. If the workspace already has a collection with that name, choose what to do first: see [When the collection already exists](#when-the-collection-already-exists).
5. Click **Import (N requests)**.

</Steps>

To pick other files, click **Choose other files**.

Luvin opens the new collection. If it has scripts, Luvin asks **Do you trust this collection?**: see [Trust a collection](/requests/scripts/#trust-a-collection).

![The dialog Do you trust this collection? over the imported collection Shop API, with the buttons Not now and Trust](/media/en/scripts-trust-dialog.webp)

### What is imported and what is not

| Imported | Not imported (the summary lists it before you import) |
|---|---|
| Folders and requests, with descriptions | Authorization types with no equivalent: those requests have no authorization |
| Saved examples | Body types with no equivalent: the body is left empty |
| Authorization of the collection, folder and request | Variables with an invalid name, and disabled variables |
| Environments and their variables | |
| Collection variables | |
| Scripts of the collection, its folders and its requests, whole (see below) | |
| Bruno `vars:post-response` and `assert` blocks, as variables and checks | |

- A variable marked as secret stays a secret. Bruno does not save its secrets' values, so they arrive empty: type them again in the environment.
- Each variable lands on its level. Postman collection variables and Bruno's collection `vars:pre-request` become [collection variables](/environments/variable-levels/); the secret ones go to the collection's environments as secrets, because a collection variable is never secret. A Postman globals file becomes a global environment of the workspace; if one with that name exists, only the variables it lacks are added. Bruno's `vars:pre-request` of a request become that request's variables.

### Scripts come over whole

Pre-request and post-response scripts come over as they are, to the **Scripts** tab of the same level: the collection, each folder and each request. They run as in Postman or Bruno, in the same order, once you trust the collection. Most scripts run without changes. See [Scripts](/requests/scripts/).

| From | Before request | After response |
|---|---|---|
| Postman | **Pre-request** | **Post-response** (**Tests**) |
| Bruno | `script:pre-request` | `script:post-response`, then `tests` |

Bruno's `vars:post-response` and `assert` blocks have no code: they become the **Variables** and **Checks** tabs of each request. See [Bruno asserts and Postman tests](/requests/checks-from-postman/).

The summary of each collection, before you import, says:

- *2 script(s) come over whole, to the Scripts tab of the collection, its folders and its requests. They run as in the original once you trust the collection.* Each level counts up to two: its before-request script and its after-response script.
- *3 Bruno variable(s) and assertion(s) went to the Variables and Checks tabs of each request.*
- A warning when some scripts use something Luvin does not have, with the names: *Some scripts use something Luvin does not have yet (pm.vault): they still run, but that part warns and fails.* See [What is not available](/requests/scripts-api/#what-is-not-available).

![The summary of the import of Shop API: 3 requests, 1 folder, 1 collection variable, and 5 scripts that come over whole to the Scripts tab](/media/en/import-scripts-summary.webp)

### When the collection already exists

If the workspace already has a collection with the same name (capitals do not matter), the summary says **A collection “Shop API” already exists in this workspace.** and offers two options:

| Option | What happens |
|---|---|
| **Import as a copy, with the name above** (the default) | A new collection. Its name gets `_v1`, `_v2`… so it does not clash, such as `Shop API_v1`. You can change it in the name field. |
| **Replace the content of “Shop API”** | The existing collection is updated with the import. *Its requests, folders, environments, variables, authorization and scripts are replaced. Its workflows, contracts, mocks and history stay. If it brings scripts, it asks again whether you trust it.* The name field is locked. |

![The summary of a second import of Shop API: A collection “Shop API” already exists in this workspace, with Import as a copy (Shop API_v1) chosen and Replace the content of “Shop API”](/media/en/import-duplicate.webp)

Use **Replace** when you export a newer version of the same Postman collection: your workflows built on it stay.

Open tabs are kept per collection. When you switch to another collection and come back, its tabs are as you left them, and a copy never shows the tabs of the original.

<Aside>
If you choose only environment files, Luvin says **Those are only environments: choose the collection too.** If it finds no collection, it says **No Postman or Bruno collection was found in what you chose.**
</Aside>

## Arazzo files and contracts

You need a collection open first. Luvin adds the files to it. Files can be `.yaml`, `.yml` or `.json`.

<Tabs>
<TabItem label="Button">

<Steps>

1. Open the workspace home with the house icon in the top bar.
2. Under **Quick actions**, click **Import Arazzo or contracts**.
3. Choose one or more files.

</Steps>

The button only appears when a collection is open. A collection with no Arazzo shows the same advice.

</TabItem>
<TabItem label="Contract, from the sidebar">

<Steps>

1. In **Contracts**, click **+** (**Add contract**).
2. Click **Import contract…**.
3. Choose the file.

</Steps>

</TabItem>
<TabItem label="Drag and drop">

<Steps>

1. Drag the files from your file explorer onto the Luvin window. It says **Drop to add to “collection name”**.
2. Drop them. A message says how many were added, for example **Added 3 file(s) to the collection**.

</Steps>

With no collection to receive them, the message is **Open or create a collection to add files to it**. Other file types are skipped and Luvin says how many.

</TabItem>
</Tabs>

<Aside type="tip">
If a contract points to other files with `$ref`, add those too. Drop the Arazzo, its contracts and the `$ref` files together. When some are missing, the contract shows ✕ in the sidebar. See [Troubleshooting](/get-started/troubleshooting/).
</Aside>

## A cURL command

A cURL command is a request written as text, like the ones Chrome, Postman or an API's documentation let you copy.

```bash
curl -X POST 'https://api.shop.test/customers' \
  -H 'Content-Type: application/json' \
  --data-raw '{"name":"Ana"}'
```

![The Import from cURL dialog with a command pasted in](/media/en/import-curl.webp)

<Steps>

1. Click **+** in the tabs (**Create or import**), then **New request**.
2. Click **Import from cURL**.
3. Paste the command. The method, URL, headers, authorization and body are converted.
4. Click **Import**.

</Steps>

The command must start with `curl` and include a URL. Otherwise Luvin says it does not look like a valid cURL command. The sidebar menus for requests also offer **Import from cURL**. To copy a step as cURL, see [cURL](/requests/curl/).

## Open files without a workspace

To try something quickly, open files with no workspace.

<Steps>

1. On the welcome screen, click **Open files without a workspace**, at the bottom. Luvin opens a folder picker.
2. Choose your contracts, your Arazzo files and the files their `$ref` point to. You can also drop them on the welcome screen.

</Steps>

If you close the welcome screen with **I’ll explore on my own**, the empty screen offers **Open files** and **Open folder**. A folder loads every YAML and JSON file inside it and its subfolders. If it has many files, only the first 300 load, and Luvin says so.
