The sidebar is the map of the open collection: its Arazzo files, workflows, steps, requests, contracts and environments, plus its history and its mock servers. Use it to open things, to see how the last run went and to find anything by name.

## Switch panels

At the top of the sidebar there are four icons. Each one shows a panel that uses the whole height of the sidebar. Point at an icon to read its name.

| Icon | The panel shows |
|---|---|
| **Collections** | The tree of your collections: Arazzo files, workflows, steps, requests, **+ New workflow**, **+ New request** and **Add files to the collection**. Below it, the **Contracts** section. |
| **Environments** | The global environments of the workspace and the environments of the open collection. See [The Environments panel](#the-environments-panel). |
| **History** | The latest 50 entries of the collection's history. **See all** opens the **History** tab. See [History](/workspaces/history/). |
| **Mock servers** | The mock servers of the collection, each with its state and port. **+** creates one. See [Mock servers](/mocks/overview/). |

- Luvin remembers the panel you chose on this computer.
- A green dot on the **Mock servers** icon means a mock is running, even when another panel is open.
- With no collection open, there are no icons: the sidebar shows only your collections.
- Drag the right border of the sidebar to change its width, from 200 to 560 px. Double-click the border to go back to the default width. Luvin remembers it on this computer.

The active environments are also always visible at the top right of the window. See [A tour of the interface](/get-started/interface/#top-bar).

## Read the tree

In the **Collections** panel, inside a collection, from top to bottom:

| Row | What it is | A click does |
|---|---|---|
| The Arazzo file | The file that holds workflows. With several files, it shows the title of the file and, below it, the file name. | Opens the [file view](/design/arazzo-file/) and unfolds the file. |
| A workflow | One workflow of the file, with a colored dot. | Opens the workflow. |
| A step | One call of the workflow, with its method (`GET`, `POST`…). | Opens a tab with that step. |
| **Requests** | The saved requests of the collection and their folders. | Opens the request. See [Requests](/requests/overview/). |
| **Contracts** | The OpenAPI and AsyncAPI files, in a section below the collections. | Opens the contract. See [Contracts](/contracts/overview/). |

The arrow before a workflow name has the tooltip **Show or hide the steps**. Click it to fold or unfold the steps without opening the workflow.

### The dot of a workflow

The dot shows how the last run of that workflow went. Point at it to read the state.

| Dot | Tooltip | Meaning |
|---|---|---|
| Empty ring | **Not run** | No case has run yet. |
| Blue, pulsing | **Running** | A case is running now. |
| Green | **Passed** | The cases that ran passed. |
| Yellow | **Warnings** or **Inconclusive** | At least one case ended with a warning, or could not be judged. |
| Red | **Failed** | At least one case failed. |
| Red, before any run | **1 error(s)** | The workflow has an error to fix before it can run. The number is how many. |

A step in red has an error. A **!** next to a file name means the file has errors. Open the **Overview** tab of the workflow to see them.

## Search in the sidebar

Use this search to filter the tree. To search everything at once and jump to a result, use [⌘K](/get-started/interface/) instead.

<Steps>

1. At the top of the sidebar, next to **Collections**, click the magnifier (**Search collections**).
2. Type in the box **Workflow, step or collection…**. The tree filters as you type.
3. Click a result to open it.
4. Press Esc, or click the magnifier again, to close the search and see everything.

</Steps>

What the search compares:

| It looks at | And shows |
|---|---|
| The name, the id and the description of a workflow | The workflow, with all its steps. |
| The name of a step or the path of its operation | The workflow, with only the steps that match. |
| The name and the URL of a request, and the name of a folder | The request, inside its folder. |
| The name of a collection | The collection. The open one always stays. |

While you search, everything that matches is unfolded. The **Contracts** section is not filtered.

**Example.** In the Pokédex collection, type `species`. The tree keeps **Pokemon card**, with the step `getSpecies`, and **Type explorer**, with `getFirstSpecies`. Both match by name, and also by the path `/pokemon-species/{idOrName}`.

## Open a step

Click a step in the sidebar and a tab opens next to the workflow tabs, named after the step. It shows, from top to bottom:

- The method and the full URL, built with the base URL of the active environment.
- The description of the step, when it has one.
- **Parameters**, with **Name**, **In** and **Value**; the body; **Success criteria**; `onSuccess` and `onFailure`; and **Outputs**.
- **Try alone**, which calls that operation outside the workflow. See [Try one operation](/contracts/try-it-out/).
- **Edit in YAML**, which opens the **YAML** tab of the workflow.

When the step has no `successCriteria`, the tab says: *No successCriteria: any 2xx response counts as success.* This tab is for reading. To change the step, use the **Design** tab.

<Aside type="tip">
In the Simple interface the same tab shows readable names and words instead of expressions. See [Preferences and the Simple interface](/get-started/preferences/).
</Aside>

## Contracts in the sidebar

Each contract row starts with a mark:

| Mark | Meaning |
|---|---|
| ✓ | The contract is loaded. |
| ✕ | It did not load. Point at it to read the reason. The row offers **Attach**, to pick the file, and **Download** when the contract has a URL. |
| ○ | The file is in the collection, but no Arazzo uses it yet. Its tooltip says *No Arazzo in the collection uses this file yet*. |

The number next to **Contracts** is how many are loaded, or `1/2` when one is missing. A **+** on an OpenAPI contract runs **Generate requests**. See [Generate requests from a contract](/requests/generate-from-contract/).

The **+** in the header of **Contracts** (**Add contract**) offers **New OpenAPI contract**, **New AsyncAPI contract** and **Import contract…**. The **⋯** of a row offers **Delete contract…** (or **Remove contract…** when there is no file). Luvin asks first. See [Contracts](/contracts/overview/).

## The Environments panel

Click the **Environments** icon at the top of the sidebar. It has two lists, and a row for the collection variables.

**Global environments**, on top, under the name of the workspace. They apply in every collection of the workspace. See [Global environments](/environments/variable-levels/#global-environments).

- Click a row to use that global environment. Click it again to use none. Its tooltip says **Use this global environment (click again: none)**.
- On the active one, **Configure** opens the Variables panel, where you edit its values.
- The **+** in the header (**New global environment**) creates one, makes it active and opens the Variables panel. The first one takes the name of the active collection environment.
- Double-click a row to rename it. The **⋯** of a row offers **Rename** and **Delete environment…**, which asks *Delete the global environment “intg” and its secrets on this device?*
- With none, the list says *They apply in every collection of the workspace. Create one with +.*

**Environments**, below, under the name of the open collection:

- The filled dot marks the active environment. A colored dot shows its [color](/environments/manage/#give-it-a-color).
- Click a row to use that environment and open it. Its tooltip says **Use and open this environment**.
- On the active one, **Configure** opens it again.
- The **+** in the header (**New environment**) creates one, makes it active and opens it.
- The **⋯** of a row offers **Delete environment…**.

At the bottom, **Collection variables** opens the **Variables** tab of the [collection overview](/workspaces/collection-overview/#collection-variables). The number next to it is how many there are.

## Without a workspace

When you opened files without a workspace, the tree shows one collection with a header: **Add files**, and **Close the collection**. Closing asks first: *Close the collection? The session and the results are discarded.* See [Open files without a workspace](/workspaces/without-workspace/).
