A step sends two kinds of data: parameters (in the path, the query or the headers) and, for some operations, a request body. You edit both in the step panel, under **Parameters**.

## Example: the body of Create order

In the PayPal example, **Create order** sends a body built from three inputs. The same body appears as fields in the panel and as `requestBody` in the file.

<Tabs>
  <TabItem label="In the app">

  Under **Body** `application/json`, each field has a **Source** list. `purchase_units/amount/currency_code` reads the input `currency`, `purchase_units/amount/value` reads `amount`, and `purchase_units/description` reads `description`. Fields inside lists are edited with **Edit as JSON**.

  ![The step panel with the fields of the request body and the buttons Fill with the example, Create inputs and Edit as JSON](/media/en/step-body.webp)

  </TabItem>
  <TabItem label="In the YAML">

```yaml title="paypal.arazzo.yaml" {5-9}
- stepId: createOrder
  operationId: $sourceDescriptions.paypal.createOrder
  requestBody:
    contentType: application/json
    payload:
      intent: CAPTURE
      purchase_units:
        - amount:
            currency_code: $inputs.currency
            value: $inputs.amount
          description: $inputs.description
```

  </TabItem>
</Tabs>

## Open the step panel

<Steps>
1. In the **Design** tab, click a step on the canvas.
</Steps>

The panel opens on the right. At the top it has the name of the step, its path and a box for its description: **What this step does (for whoever reads the workflow)**.

## Edit a parameter

Parameters are grouped by where they travel: **Path**, **Query**, **Headers** and **Cookies**. The number next to each title is how many parameters the group has.

Each parameter is a row with its name and a list, **Source**, that says where its value comes from. [Connect data between steps](/design/wire-data/) explains every option of that list.

| Mark | Meaning |
|---|---|
| `*` | The contract requires this value. |
| **extra** | The contract does not declare it. Someone added it by hand, for example in the YAML. |
| ♻ | It comes from a [reusable](/design/reusables/). |

If the operation has no parameters and no body, the panel says **This operation takes no parameters.**

For query parameters in action, see [Query parameters and paging](/recipes/pagination-query/).

### A value inside a text

Some values mix fixed text with data, such as a token after `Bearer`. Choose **Fixed value…** and write the expression between braces inside the text: `Bearer {$steps.login.outputs.token}`. Luvin replaces it when the step runs. The canvas draws no data line for it, because the value is not only the output.

![The Authorization header of createOrder with the fixed value Bearer and the token of the login step](/media/en/design-token-header.webp)

## Send an optional parameter

Optional parameters are not sent until you give them a source. They stay folded on one line: **Optional, not sent: limit, offset**.

<Steps>
1. Click **Edit** on that line. A row appears for each optional parameter.
2. In the row you want, open **Source** and choose where the value comes from, for example **Fixed value…** and then `20`.
3. Click **Hide the ones not sent** to fold the rest again.
</Steps>

To stop sending it, choose **Don't send** in its **Source** list.

![The optional query parameters limit and offset unfolded, each with Don’t send, and the link Hide the ones not sent](/media/en/design-optional-params-open.webp)

## Fill in the request body

When the operation takes a body, a last group appears: **Body**, followed by its format, for example `application/json`.

- The group lists every field the contract declares, required and optional.
- A field inside an object is shown with its path: `amount/value`.
- Each field has the same **Source** list as a parameter. Optional fields without a value fold away.
- A fixed value you type in a number field is sent as a number. `true` or `false` in a yes/no field is sent as a boolean.

Three buttons above the fields work on the whole body:

| Button | What it does | When it appears |
|---|---|---|
| **Fill with the example** | Puts the contract's example value in the empty fields. You can change them afterwards. | The contract has an example for the body or for its empty fields. |
| **Create inputs** | Creates one workflow input per empty field, with the contract's example as its value, and connects it. If an input with that name exists, it is used. You fill the inputs in the **Inputs** tab and cases can vary them. | Some field of the contract is empty. |
| **Edit as JSON** | Opens the whole body as text. | Always. |

<Aside type="note">
**Fill with the example** and **Create inputs** skip the fields inside lists. For those, use **Edit as JSON**.
</Aside>

## Edit the body as JSON

Use it for lists, nested objects or fields the contract does not declare.

<Steps>
1. Click **Edit as JSON**. A text box opens.
2. Edit the JSON.
3. Click **Apply**, or press ⌘ + Enter (Ctrl + Enter on Windows). **Cancel** closes the box without changes.
</Steps>

The box starts from what the step already has. If the body is empty, it starts from the contract's example or, when there is none, from every field of the contract with its example value. In that case the box says **Starts from the contract's fields; nothing is saved until you press Apply.**

To take a value from somewhere else, write the reference as a text:

| You write | The step sends |
|---|---|
| `"$inputs.amount"` | The input `amount` of the workflow. |
| `"$steps.createOrder.outputs.orderId"` | The output `orderId` of the step `createOrder`. |

This is the body of **Create order** in the PayPal example:

```json title="Edit as JSON" {6-7}
{
  "intent": "CAPTURE",
  "purchase_units": [
    {
      "amount": {
        "currency_code": "$inputs.currency",
        "value": "$inputs.amount"
      },
      "description": "$inputs.description"
    }
  ]
}
```

If the text is not valid JSON, the box shows **The JSON isn't valid:** with the reason, and nothing changes. To remove the body, empty the box and click **Apply**.

To build a body from random data, see [Generated data in the body](/recipes/generated-data/).

![The Edit as JSON box of createOrder with an address object and a lines list, and the Cancel and Apply buttons](/media/en/design-body-json.webp)

## Turn a fixed value into an input

A fixed value is always the same. Turn it into an input when you want cases to try other values: empty, invalid, other data.

<Steps>
1. On the canvas, point at the fixed value on the step's card. **→ input** appears next to it.
2. Click **→ input**.
</Steps>

The workflow gets a new input with the current value as its value, so it runs as before, and the step now reads the input.

To do several at once, use the **Start** card: **Choose variable data…** when the workflow has no inputs, or **+ Turn another fixed value into an input** when it has some. A dialog, **Data to vary per case**, lists every fixed value. Tick the ones you want and click **Turn into inputs**. If the same value is used in several steps, a single input feeds them all.

![The card of createOrder with the → input button next to the fixed value of currency](/media/en/design-promote-one.webp)

![The dialog Data to vary per case: each fixed value with where it is, its value and the input it would become](/media/en/design-pick-data.webp)

You should see the new inputs on **Start**, and the values on the card now read them.

![Start with the inputs currency and city, created from fixed values, and their data lines](/media/en/design-promoted.webp)

### Turn an input back into a fixed value

There is no single button for this. Do it in two moves:

<Steps>
1. Click the step and, in the **Source** list of the value, choose **Fixed value…**. Type the value. The field stays in view while you edit it, also when it is optional.
2. Click **Start** and delete the input with its bin, if no other step uses it.
</Steps>

If you delete an input that a step still uses, the bar **This workflow is missing data** appears. See [Complete missing data](/design/complete-gaps/). Right after turning values into inputs, **Undo** also brings the fixed values back.
