Every workflow lives in an Arazzo file inside a collection. This page shows how to create that file, how to add more workflows to it, and how to give each one a name and a description.

## Example: the Pokédex file

The Pokédex collection has one Arazzo file with four workflows. It points to the contracts it uses.

<Tabs>
  <TabItem label="In the collection">

<FileTree>
- pokemon.arazzo.yaml the file with the four workflows
- pokeapi.openapi.yaml
- pokedex-events.asyncapi.yaml
</FileTree>

  </TabItem>
  <TabItem label="Inside the file">

```yaml title="pokemon.arazzo.yaml" {2-3,5-6,10}
sourceDescriptions:
  - name: pokeapi
    url: ./pokeapi.openapi.yaml
    type: openapi
workflows:
  - workflowId: pokemonCard
    summary: Pokemon card
    steps:
      - stepId: getPokemon
        # ...
```

  </TabItem>
</Tabs>

`sourceDescriptions` lists the contracts. Each item of `workflows` is one workflow, with its `workflowId`, its `summary` and its `steps`.

## What an Arazzo file is

[Arazzo](https://spec.openapis.org/arazzo/latest.html) is an open standard of the OpenAPI Initiative for describing sequences of API calls. An Arazzo file is a text file in your collection, for example `pokemon.arazzo.yaml`, with two things inside:

- The list of contracts it uses (the OpenAPI and AsyncAPI files of your APIs).
- One or more workflows built from the operations of those contracts.

You do not need to read or write this file. The **Design** tab edits it for you, and the [YAML tab](/design/arazzo-editor/) shows it when you want to look.

One file can hold several workflows. The Pokédex example has one file with four: **Pokemon card**, **Type explorer**, **Battle matchup** and **Register sighting**.

<Aside type="tip" title="One file or several?">
Put workflows in the same file when one of them uses another: the canvas offers them first. A workflow can also call or depend on a workflow of another Arazzo file of the same collection. See [Workflows that use other workflows](/design/dependencies/).
</Aside>

## Create a new Arazzo file

You need an open collection.

<Steps>
1. Click **+** (**Create or import**) to the right of the open tabs.
2. Choose **New Arazzo**.
</Steps>

![The + menu next to the tabs, with New request, New workflow in this file and New Arazzo](/media/en/design-plus-menu.webp)

Luvin creates the file `new.arazzo.yaml` in the collection, adds the contracts of the collection to it, and opens its first workflow, **My workflow**, in the **Design** tab. The canvas is empty and shows the card **Build your workflow**, with **Add the first step**.

If a file with that name already exists, the new one is called `new-2.arazzo.yaml`, and so on.

<Aside type="tip">
In a workspace, the **⋯** menu of a collection in the sidebar has the same action: **New Arazzo file**. To change the file name later, open the **⋯** menu of the file in the sidebar and choose **Rename**.
</Aside>

![A new Arazzo file: the workflow My workflow opens in Design with Start, End of workflow and the card Build your workflow](/media/en/design-new-arazzo.webp)

## Add a workflow to an existing file

<Steps>
1. Open any workflow of that file.
2. Click **+** (**Create or import**) to the right of the open tabs.
3. Choose **New workflow in this file**.
</Steps>

A new, empty workflow called **New workflow** is added to the same file and opens in the **Design** tab. It also appears in the sidebar, under the file.

**+ New workflow** in the sidebar, under the collection, and **Design a workflow**, the first of the **Quick actions** on **Home**, do the same. They add the workflow to the file you are looking at, or to the first Arazzo file of the collection. If the collection has no Arazzo file yet, they create one.

## Name and describe a workflow

The name and the description are at the top of the workflow, to the left of the **Run** button.

### Change the name

<Steps>
1. Click the name. It becomes a text field.
2. Type the new name.
3. Press Enter. Press Esc to cancel.
</Steps>

While you type, a line below shows **id in the Arazzo:** followed by an identifier, for example `battleMatchup` for "Battle matchup". The id is your name without spaces, accents or symbols. It is what the file uses to refer to the workflow; the sidebar and the tabs keep showing the name as you wrote it.

| Message | What to do |
|---|---|
| **Type a name with at least one letter or number.** | The name only had spaces or symbols. Add a letter or a number. |
| **There is already a workflow «…» in this file.** | Another workflow of the file has that id. Choose a different name. |

Renaming is safe. Luvin updates everything in the file that points to the workflow: the workflows that depend on it, the steps that call it and the values that read its outputs. Its cases stay with it.

![The name of the workflow being edited, with the line id in the Arazzo: below it](/media/en/design-rename.webp)

### Change the description

<Steps>
1. Click the text below the name. If the workflow has no description, it says **Add a short description**.
2. Type one sentence that says what the workflow does, for example "Creates an order and reads it back".
3. Press Enter.
</Steps>

A new workflow starts with the placeholder **Describe here what this workflow does**. Replace it: the description is shown next to the workflow's name wherever another workflow picks it, such as the **Workflows in this Arazzo** group of **＋ Step**.

## What you have now

An empty workflow has **▶ Start · no inputs** at the top, **■ End of workflow · no outputs** at the bottom, and the card **Build your workflow** in the middle. The steps go between Start and End. Inputs appear on their own when a step needs data nobody provides.
