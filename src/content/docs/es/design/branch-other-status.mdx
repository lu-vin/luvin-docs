Los contratos suelen dejar fuera status que cualquier API puede responder: 429 cuando mandas demasiados requests, 503 durante un mantenimiento, 500 cuando falla el servidor. El editor de rutas acepta cualquier status, esté declarado o no.

## Ejemplo: reintentar un 429 de getPokemon

El contrato de la PokéAPI no declara el 429 para `getPokemon`.

<Steps>
1. Abre **Pokemon card** y haz clic en la pestaña **Diseño**.
2. En la tarjeta de `getPokemon`, haz clic en **＋ Qué hacer si falla**.
3. En **Si responde**, escribe `429`. Los status que aparecen junto a **el contrato dice:** no lo incluyen, y no pasa nada.
4. Haz clic en **Reintentar**, deja **Esperar** `2` **s, hasta** `3` **veces** y haz clic en **Agregar**.
</Steps>

<Tabs>
<TabItem label="En el lienzo">

La tarjeta queda con la fila `429 ↻ reintenta hasta 3 · cada 2 s`, con un lazo azul que vuelve a la tarjeta.

</TabItem>
<TabItem label="En el YAML">

```yaml title="pokemon.arazzo.yaml"
onFailure:
  - name: pokemonNotFound
    type: end
    criteria:
      - condition: $statusCode == 404
  - name: retry429
    type: retry
    retryAfter: 2
    retryLimit: 3
    criteria:
      - condition: $statusCode == 429
```

</TabItem>
</Tabs>

## Qué status puedes escribir

**Si responde** acepta solo dígitos, hasta tres. Lo demás se descarta mientras escribes. **Agregar** queda desactivado hasta que el status tenga tres dígitos y hayas elegido qué hacer.

Una ruta de fallo solo se ejecuta cuando el paso falla. Un status que el paso ya cuenta como éxito, como su 200, nunca llega a ella.

## Un status para todos los pasos

Cuando el mismo status puede venir de cualquier llamada, como un 429 por límite de uso o un 503 por mantenimiento, agrégalo una sola vez como regla del workflow en vez de una ruta por paso. Abre **Inicio**, haz clic en **＋ Regla para todos los pasos** y completa el editor igual. Ver [Reglas para todos los pasos](/es/design/routes-panel/#reglas-para-todos-los-pasos).

## Status frecuentes

| Status | Qué suele significar | Una ruta razonable |
|---|---|---|
| 401 | El token venció | **Renovar y reintentar**, con el workflow del login. |
| 409 | Conflicto con el estado actual | **Ir a otro paso**, por ejemplo uno que lea el estado actual. |
| 429 | Demasiados requests | **Reintentar**. Sube **Esperar** si la API pide esperar más. |
| 500 | Falló el servidor | **Terminar el workflow**, o ninguna ruta, para que la ejecución falle y lo veas. |
| 503 | Servicio no disponible | **Reintentar**, o **Terminar el workflow**. |

Luvin espera solo lo que dice la ruta. No lee el header `Retry-After` de la respuesta.

## Status declarados sin ruta: un clic

Un status que el contrato declara y que nada maneja es una fila roja en la tarjeta, `422 ✕ sin ruta: el workflow falla`. En la pestaña **Éxito y rutas** del panel del paso, ese status tiene tres botones:

| Botón | Qué agrega |
|---|---|
| **Termina** | Una ruta que termina el workflow con ese status. El aviso dice **Ruta agregada: si responde 422, termina el workflow.** |
| **Reintenta** | Una ruta que reintenta el paso cada 2 segundos, hasta 3 veces. El aviso dice **Ruta agregada: si responde 422, reintenta cada 2 s, hasta 3 veces.** |
| **Elegir qué hacer** | El editor de rutas, con el status ya puesto. |

Cada aviso tiene **Deshacer**.

## Qué ves después

| Dónde | Qué aparece |
|---|---|
| La tarjeta | La fila de la ruta nueva, con su flecha, y un lápiz para cambiarla. |
| La pestaña **Éxito y rutas** | La ruta en la lista **Rutas**, en palabras y con su línea de Arazzo. |
| [Por revisar](/es/design/review/) | Si el status estaba declarado, uno menos **sin ruta**. |
| **Casos** | Un caso generado, **getPokemon responde 429 → retry429**, que simula esa respuesta. |
| Resultados de una ejecución real que recibió un 429 | El paso avisa **El código 429 no está documentado en el contrato de …**. |

Ese último mensaje es una pista, no un error de tu workflow. Si la API de verdad responde ese status, agrégalo al contrato: entonces aparece junto a **el contrato dice:**, y como fila roja mientras nada lo maneje. Ver [Editar un contrato](/es/contracts/edit/).
