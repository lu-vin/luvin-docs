Un paso envía dos clases de datos: parámetros (en la ruta, en el query o en los headers) y, en algunas operaciones, un body. Editas ambos en el panel del paso, bajo **Parámetros**.

## Ejemplo: el body de Create order

En el ejemplo de PayPal, **Create order** envía un body armado con tres inputs. El mismo body aparece como campos en el panel y como `requestBody` en el archivo.

<Tabs>
  <TabItem label="En la app">

  Bajo **Body** `application/json`, cada campo tiene una lista **Origen**. `purchase_units/amount/currency_code` lee el input `currency`, `purchase_units/amount/value` lee `amount` y `purchase_units/description` lee `description`. Los campos dentro de listas se editan con **Editar como JSON**.

  ![El panel de un paso con los campos del body y los botones Rellenar con el ejemplo, Crear inputs y Editar como JSON](/media/es/step-body.webp)

  </TabItem>
  <TabItem label="En el YAML">

```yaml title="paypal.arazzo.yaml" {5-9}
- stepId: createOrder
  operationId: $sourceDescriptions.paypal.createOrder
  requestBody:
    contentType: application/json
    payload:
      intent: CAPTURE
      purchase_units:
        - amount:
            currency_code: $inputs.currency
            value: $inputs.amount
          description: $inputs.description
```

  </TabItem>
</Tabs>

## Abre el panel del paso

<Steps>
1. En la pestaña **Diseño**, haz clic en un paso del lienzo.
</Steps>

El panel se abre a la derecha. Arriba tiene el nombre del paso, su ruta y una caja para su descripción: **Qué hace este paso (para quien lea el workflow)**.

## Edita un parámetro

Los parámetros se agrupan según por dónde viajan: **Ruta**, **Query**, **Headers** y **Cookies**. El número junto a cada título es cuántos parámetros tiene el grupo.

Cada parámetro es una fila con su nombre y una lista, **Origen**, que dice de dónde sale su valor. [Conectar datos entre pasos](/es/design/wire-data/) explica cada opción de esa lista.

| Marca | Significado |
|---|---|
| `*` | El contrato exige este valor. |
| **extra** | El contrato no lo declara. Alguien lo agregó a mano, por ejemplo en el YAML. |
| ♻ | Viene de un [reutilizable](/es/design/reusables/). |

Si la operación no tiene parámetros ni body, el panel dice **Esta operación no recibe parámetros.**

Para ver parámetros de query en acción, mira [Parámetros de query y paginación](/es/recipes/pagination-query/).

### Un valor dentro de un texto

Algunos valores mezclan texto fijo con datos, como un token después de `Bearer`. Elige **Valor fijo…** y escribe la expresión entre llaves dentro del texto: `Bearer {$steps.login.outputs.token}`. Luvin la reemplaza al ejecutar el paso. El lienzo no dibuja una línea de datos para él, porque el valor no es solo el output.

![La cabecera Authorization de createOrder con el valor fijo Bearer y el token del paso login](/media/es/design-token-header.webp)

## Envía un parámetro opcional

Los parámetros opcionales no se envían hasta que les das un origen. Quedan plegados en una línea: **Opcionales sin enviar: limit, offset**.

<Steps>
1. Haz clic en **Editar** en esa línea. Aparece una fila por cada parámetro opcional.
2. En la fila que quieras, abre **Origen** y elige de dónde sale el valor, por ejemplo **Valor fijo…** y luego `20`.
3. Haz clic en **Ocultar los que no se envían** para plegar el resto otra vez.
</Steps>

Para dejar de enviarlo, elige **No enviar** en su lista **Origen**.

![Los parámetros opcionales limit y offset desplegados, cada uno con No enviar, y el enlace Ocultar los que no se envían](/media/es/design-optional-params-open.webp)

## Completa el body

Cuando la operación recibe un body, aparece un último grupo: **Body**, seguido de su formato, por ejemplo `application/json`.

- El grupo lista todos los campos que declara el contrato, obligatorios y opcionales.
- Un campo dentro de un objeto se muestra con su ruta: `amount/value`.
- Cada campo tiene la misma lista **Origen** que un parámetro. Los campos opcionales sin valor se pliegan.
- Un valor fijo que escribes en un campo numérico se envía como número. `true` o `false` en un campo de sí/no se envía como booleano.

Tres botones sobre los campos trabajan sobre todo el body:

| Botón | Qué hace | Cuándo aparece |
|---|---|---|
| **Rellenar con el ejemplo** | Pone el valor de ejemplo del contrato en los campos vacíos. Después puedes cambiarlos. | El contrato tiene un ejemplo para el body o para sus campos vacíos. |
| **Crear inputs** | Crea un input del workflow por cada campo vacío, con el ejemplo del contrato como valor, y lo conecta. Si ya existe un input con ese nombre, lo usa. Llenas los inputs en la pestaña **Inputs** y los casos pueden variarlos. | Algún campo del contrato está vacío. |
| **Editar como JSON** | Abre todo el body como texto. | Siempre. |

<Aside type="note">
**Rellenar con el ejemplo** y **Crear inputs** se saltan los campos que están dentro de listas. Para esos, usa **Editar como JSON**.
</Aside>

## Edita el body como JSON

Úsalo para listas, objetos anidados o campos que el contrato no declara.

<Steps>
1. Haz clic en **Editar como JSON**. Se abre una caja de texto.
2. Edita el JSON.
3. Haz clic en **Aplicar**, o pulsa ⌘ + Enter (Ctrl + Enter en Windows). **Cancelar** cierra la caja sin cambios.
</Steps>

La caja parte de lo que el paso ya tiene. Si el body está vacío, parte del ejemplo del contrato o, cuando no hay, de todos los campos del contrato con su valor de ejemplo. En ese caso la caja dice **Parte de los campos del contrato; nada se guarda hasta que pulses Aplicar.**

Para tomar un valor de otro lugar, escribe la referencia como texto:

| Escribes | El paso envía |
|---|---|
| `"$inputs.amount"` | El input `amount` del workflow. |
| `"$steps.createOrder.outputs.orderId"` | El output `orderId` del paso `createOrder`. |

Este es el body de **Create order** en el ejemplo de PayPal:

```json title="Editar como JSON" {6-7}
{
  "intent": "CAPTURE",
  "purchase_units": [
    {
      "amount": {
        "currency_code": "$inputs.currency",
        "value": "$inputs.amount"
      },
      "description": "$inputs.description"
    }
  ]
}
```

Si el texto no es un JSON válido, la caja muestra **El JSON no es válido:** con el motivo, y no cambia nada. Para quitar el body, vacía la caja y haz clic en **Aplicar**.

Para armar un body con datos aleatorios, mira [Datos generados en el body](/es/recipes/generated-data/).

![La caja Editar como JSON de createOrder con un objeto address y una lista lines, y los botones Cancelar y Aplicar](/media/es/design-body-json.webp)

## Convierte un valor fijo en un input

Un valor fijo siempre es el mismo. Conviértelo en un input cuando quieras que los casos prueben otros valores: vacíos, inválidos, otros datos.

<Steps>
1. En el lienzo, apunta al valor fijo en la tarjeta del paso. Junto a él aparece **→ input**.
2. Haz clic en **→ input**.
</Steps>

El workflow recibe un input nuevo con el valor actual como valor, así que se ejecuta igual que antes, y el paso ahora lee el input.

Para hacer varios a la vez, usa la tarjeta **Inicio**: **Elegir datos variables…** cuando el workflow no tiene inputs, o **+ Volver input otro valor fijo** cuando ya tiene algunos. Un diálogo, **Datos para variar por caso**, lista cada valor fijo. Marca los que quieras y haz clic en **Convertir en inputs**. Si el mismo valor se usa en varios pasos, un solo input los alimenta a todos.

![La tarjeta de createOrder con el botón → input junto al valor fijo de currency](/media/es/design-promote-one.webp)

![El diálogo Datos para variar por caso: cada valor fijo con dónde está, su valor y el input en que se convertiría](/media/es/design-pick-data.webp)

Debes ver los inputs nuevos en **Inicio**, y los valores de la tarjeta ahora los leen.

![Inicio con los inputs currency y city, creados desde valores fijos, y sus líneas de datos](/media/es/design-promoted.webp)

### Vuelve un input a valor fijo

No hay un solo botón para esto. Hazlo en dos movimientos:

<Steps>
1. Haz clic en el paso y, en la lista **Origen** del valor, elige **Valor fijo…**. Escribe el valor. El campo sigue a la vista mientras lo editas, también si es opcional.
2. Haz clic en **Inicio** y borra el input con su papelera, si ningún otro paso lo usa.
</Steps>

Si borras un input que un paso todavía usa, aparece la barra **A este workflow le faltan datos**. Ver [Completa los datos que faltan](/es/design/complete-gaps/). Justo después de convertir valores en inputs, **Deshacer** también trae de vuelta los valores fijos.
