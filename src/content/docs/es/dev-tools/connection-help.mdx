Cuando una ejecución contra la **API real** no recibe respuesta de la API, Luvin muestra un panel llamado **No se pudo conectar con la API**. Te dice qué revisar y qué puedes hacer después. No tienes que abrirlo: aparece solo sobre los resultados.

## Cuándo aparece

El panel aparece cuando un paso no pudo conectarse: el servidor no respondió, la dirección no existe o tu equipo no llega a ella. No aparece cuando la API responde con un error como 401 o 500. Eso son resultados, y los lees en los [resultados](/es/test/results/).

La primera línea dice cuántos casos están afectados y qué servidores no respondieron:

```text
3 caso(s) no obtuvieron respuesta de https://api.shop.test. Suele ser una de estas causas:
```

Haz clic en la **×** (**Cerrar**) para ocultar el panel.

![El panel "No se pudo conectar con la API", con el enlace para abrir la dirección y los botones para probar en simulación o revisar el ambiente](/media/es/connection-help.webp)

## Qué revisa

### ¿La URL es correcta y el servidor está encendido?

Abre la dirección: si no carga, el problema no es Luvin. El panel da un enlace por servidor, **Abrir https://api.shop.test ↗**. Si la dirección está mal, corrígela en el ambiente (mira más abajo).

## Qué puedes hacer desde el panel

| Botón | Qué hace |
|---|---|
| **Probar en simulación** | Ejecuta de nuevo este workflow en **Simulación**, sin red. Sirve para seguir trabajando mientras arreglan la API. |
| **Revisar ambiente** | Abre el ambiente activo, para revisar la URL base. |

Al final, el panel te recuerda que puedes copiar un paso como cURL y probarlo en tu terminal, para ver el error tal cual. Mira [Network](/es/dev-tools/network/).

<Aside type="tip">
Si a la API solo se llega por un proxy o pide un certificado de cliente, configúralos en [Preferencias → Red](/es/get-started/network/).
</Aside>
