Cuando importas una colección, sus pruebas siguen funcionando. Los tests de Postman y los scripts de Bruno se traen completos, a la pestaña **Scripts**, y corren como en el original cuando confías en la colección. Los bloques `vars:post-response` y `assert` de Bruno, que no tienen código, pasan a las pestañas **Variables** y **Comprobaciones** de cada request.

Esta página lista qué pasa a ser una comprobación, y cómo pasar a mano una prueba de un script a una comprobación, si prefieres comprobaciones sin código.

## A dónde va cada parte

| Desde | Va a |
|---|---|
| Postman: el script **Pre-request** de la colección, una carpeta o un request | El script **Antes del request** del mismo nivel |
| Postman: el script **Tests** (post-response) de la colección, una carpeta o un request | El script **Después de la respuesta** del mismo nivel |
| Bruno: `script:pre-request` de `collection.bru`, `folder.bru` o un request | El script **Antes del request** del mismo nivel |
| Bruno: `script:post-response` y `tests` | El script **Después de la respuesta** del mismo nivel, primero uno y luego el otro |
| Bruno: `vars:post-response` de un request | La pestaña **Variables** del request |
| Bruno: `assert` de un request | La pestaña **Comprobaciones** del request |

Funciona desde una carpeta de archivos `.bru` y desde el `.json` que exporta Bruno. Mira [Scripts](/es/requests/scripts/) e [Importar de Postman o Bruno](/es/get-started/import/#los-scripts-se-traen-completos).

## Bloques de Bruno que pasan a variables y comprobaciones

```
vars:post-response {
  token: res.body.token
}
assert {
  res.status: eq 200
  res.body.name: isString
  res.body.types: isNotEmpty
  ~res.body.order: gt 0
}
```

Después de importar, el request tiene:

| Pestaña | Fila |
|---|---|
| **Variables** | `token` ← `res.body.token` |
| **Comprobaciones** | `res.status` **es igual a** `200` |
| **Comprobaciones** | `res.body.name` **es texto** |
| **Comprobaciones** | `res.body.types` **no está vacío** |
| **Comprobaciones** | `res.body.order` **es mayor que** `0`, desmarcada (estaba desactivada en Bruno con `~`) |

El operador de cada línea de `assert` tiene que ser uno de los [nombres en el archivo](/es/requests/check-operators/#todas-las-comprobaciones) de Luvin, que son los mismos de Bruno. Una línea con un operador que Luvin no tiene, como `between`, se omite.

El lado izquierdo tiene que ser algo que Luvin pueda leer de la respuesta:

| En Bruno | En Luvin |
|---|---|
| `res.body.id`, `res.getBody().id`, `res("id")` | `res.body.id` |
| `res.body.items[0].id` | `res.body.items[0].id` |
| `res.status`, `res.getStatus()` | `res.status` |
| `res.responseTime`, `res.getResponseTime()` | `res.responseTime` |
| `res.getHeader("X-Id")`, `res.headers["X-Id"]` | `res.headers.x-id` |

### Qué dice el resumen

Antes de importar, el resumen de la colección dice *3 variable(s) y assertion(s) de Bruno pasaron a las pestañas Variables y Comprobaciones de cada request.* Si se omitió una línea, avisa: *Algunas assertions o variables de respuesta de Bruno no se pudieron pasar a Comprobaciones o Variables.* Escribe esas líneas a mano en la pestaña **Comprobaciones**, o como prueba en el script **Después de la respuesta**.

## Pasar una prueba de un script a una comprobación

Una prueba en un script y una comprobación en la pestaña **Comprobaciones** pueden decir lo mismo. Las comprobaciones no necesitan código, se revisan más fácil y se ven junto al status. Para pasar una prueba a la pestaña **Comprobaciones**, usa estas equivalencias y después borra la prueba del script.

```js
const jsonData = pm.response.json();
pm.test("It is Pikachu", function () {
  pm.response.to.have.status(200);
  pm.expect(jsonData.name).to.eql("pikachu");
  pm.expect(jsonData.types).to.be.an("array");
  pm.expect(pm.response.responseTime).to.be.below(1000);
});
```

equivale a estas comprobaciones:

| De la respuesta | Comprobación | Valor esperado |
|---|---|---|
| `res.status` | **es igual a** | `200` |
| `res.body.name` | **es igual a** | `pikachu` |
| `res.body.types` | **es una lista** | |
| `res.responseTime` | **es menor que** | `1000` |

### Lo que lee el script

| En el script | De la respuesta |
|---|---|
| `pm.response.json().id`, `jsonData.id` (después de `const jsonData = pm.response.json()`) | `res.body.id` |
| `pm.response.code` | `res.status` |
| `pm.response.responseTime` | `res.responseTime` |
| `pm.response.headers.get("X-Id")` | `res.headers.x-id` (los nombres de los headers en minúsculas) |

### La cadena

| Cadena | Comprobación |
|---|---|
| `pm.response.to.have.status(201)` | `res.status` **es igual a** `201` |
| `pm.response.to.be.ok`, `pm.response.to.be.success` | `res.status` **es mayor o igual a** `200` y **es menor que** `300` |
| `pm.response.to.have.header("X-Id")` | `res.headers.x-id` **existe** |
| `.to.eql(x)`, `.to.equal(x)` | **es igual a** |
| `.to.not.eql(x)` | **no es igual a** |
| `.to.be.above(x)`, `.to.be.at.least(x)` | **es mayor que**, **es mayor o igual a** |
| `.to.be.below(x)`, `.to.be.at.most(x)` | **es menor que**, **es menor o igual a** |
| `.to.include(x)`, `.to.not.include(x)` | **contiene**, **no contiene** |
| `.to.match(/…/)` | **coincide con (regex)** |
| `.to.exist`, `.to.not.exist` | **existe**, **no existe** |
| `.to.be.null`, `.to.be.empty`, `.to.not.be.empty` | **es null**, **está vacío**, **no está vacío** |
| `.to.be.ok` | **es verdadero** |
| `.to.be.a("string")`, `"number"`, `"boolean"`, `"array"`, `"object"` | **es texto**, **es número**, **es true/false**, **es una lista**, **es un objeto** |
| `pm.expect(jsonData).to.have.property("id")` | `res.body.id` **existe** |
| `pm.expect(jsonData.items).to.have.lengthOf(3)` | `res.body.items.length` **es igual a** `3` |
| `pm.expect(jsonData.id).to.eql(pm.environment.get("orderId"))` | `res.body.id` **es igual a** `{{orderId}}` |

### Qué dejar como script

Déjala en el script cuando la prueba:

- solo tiene sentido con una condición, como `if (pm.response.code === 404)`;
- recorre una lista, como cada elemento de `jsonData.items`;
- calcula el valor esperado, como una suma o una fecha;
- guarda un valor que tiene que seguir ahí después de cerrar Luvin (`pm.environment.set`). La pestaña **Variables** conserva los valores solo mientras la colección está abierta.
