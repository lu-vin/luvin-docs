Un request gRPC llama a un método de un servicio gRPC. Le das a Luvin el archivo `.proto` que describe el servicio, eliges el método y escribes el mensaje como JSON.

## Ejemplo

Una llamada al método `SayHello` del servicio `helloworld.Greeter`, con el mensaje `{"name": "Ana"}` y un token como metadata, se guarda así:

```yaml title="requests/say-hello.request.yaml"
name: Say hello
kind: grpc
url: localhost:50051
metadata:
  - key: authorization
    value: Bearer {{token}}
proto: protos/helloworld.proto
service: helloworld.Greeter
rpc: SayHello
message: |-
  {
    "name": "Ana"
  }
```

El `.proto` se importó en la carpeta `protos/` de la colección. Pulsa **Invocar** y la respuesta muestra el estado `0 OK` y el mensaje que devolvió el servidor.

## Crear un request gRPC

<Steps>

1. En la barra lateral, haz clic en **Nuevo request** debajo de tu colección.
2. En el diálogo **Nuevo request**, elige **gRPC**.
3. El request se abre con el nombre **Nueva llamada gRPC** y la dirección `localhost:50051`.

</Steps>

## Llamar a un método

<Steps>

1. Escribe la dirección del servidor como `host:puerto`, por ejemplo `localhost:50051`.
2. Si el servidor usa una conexión segura, marca **TLS**.
3. En el selector **.proto**, elige **Importar .proto…** y selecciona el archivo. Si el archivo importa otros archivos `.proto`, selecciónalos todos a la vez.
4. En el selector **Método**, elige el método. Los métodos están agrupados por servicio.
5. En la pestaña **Mensaje**, escribe el mensaje como JSON. Cuando eliges un método y el mensaje sigue vacío, Luvin completa un mensaje de ejemplo con todos los campos. **Usar mensaje de ejemplo** vuelve a poner el ejemplo en cualquier momento.
6. Pulsa **Invocar**. La respuesta aparece debajo.

</Steps>

El botón **Invocar** queda deshabilitado hasta que el request tiene una dirección y un método.

## El archivo .proto

Luvin necesita el `.proto` para conocer los servicios, los métodos y la forma de los mensajes. No se los pide al servidor: no usa server reflection.

- Los archivos importados se guardan en la colección, en una carpeta `protos/`. Viajan con la colección como cualquier otro archivo.
- Una vez importado, un `.proto` aparece en el selector **.proto** de todos los requests gRPC de la colección.
- Si el archivo no se puede leer, el error aparece debajo de los selectores.

## Mensaje y metadata

| Pestaña | Qué contiene |
|---|---|
| **Mensaje** | El mensaje del request, como JSON. Los nombres de los campos son los del `.proto`. |
| **Metadata** | Una tabla de clave y valor, que se envía como metadata de gRPC. |

Un request gRPC no tiene pestaña de autorización. Si el servicio necesita un token, agrégalo como metadata, por ejemplo la clave `authorization` con el valor `Bearer {{token}}`.

Las `{{variables}}` del ambiente funcionan en la dirección, el mensaje y la metadata.

## La respuesta

La respuesta muestra:

- El código de estado gRPC y su nombre, por ejemplo `0 OK` o `5 NOT_FOUND`, y el tiempo que tomó.
- **Respuesta**: cada mensaje que devolvió el servidor, como JSON. Si hay varios, se numeran y el encabezado dice cuántos son.
- **Metadata** y **Trailers**: lo que el servidor envió antes y después de los mensajes.

Cuando el estado no es `0`, los detalles que dio el servidor aparecen debajo del estado. **Copiar** copia los mensajes.

## Límites del streaming

Los métodos con streaming están marcados en el selector **Método** como `client stream`, `server stream` o ambos.

| Tipo de método | Qué hace Luvin |
|---|---|
| Unary | Envía el mensaje y muestra la única respuesta. |
| Server streaming | Envía el mensaje y muestra cada respuesta que llega. |
| Client streaming | Envía un solo mensaje, cierra el envío y muestra la respuesta. |
| Bidirectional | Envía un solo mensaje, cierra el envío y muestra cada respuesta que llega. |

Otros límites:

- No puedes enviar varios mensajes en un client stream.
- Luvin conserva hasta 500 mensajes de respuesta de un stream.
- Una llamada tiene 30 segundos para terminar. Pasado ese tiempo termina con el estado `DEADLINE_EXCEEDED`.
- Un request gRPC no se puede usar como paso de un workflow.
