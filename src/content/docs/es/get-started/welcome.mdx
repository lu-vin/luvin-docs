Luvin es una herramienta de **ingeniería de workflows de APIs**. Cuando un proceso de negocio pasa por varias APIs, Luvin te deja diseñar ese proceso de forma visual, ver cómo viajan los datos de una llamada a la siguiente, probar sus escenarios y compartir evidencia de que funciona.

Lee esta página para decidir si te sirve y después sigue el [inicio rápido](/es/get-started/quick-start/).

## El problema

Una sola pantalla de una app suele depender de varias APIs llamadas en orden. Piensa en una tienda:

<Steps>

1. Inicias sesión en la API **A** y obtienes un token.
2. Llamas a la API **B** con ese token y obtienes el cliente.
3. Llamas a la API **C** con el id del cliente y obtienes sus pedidos.

</Steps>

Para probar **C**, primero llamas a **A** y a **B** a mano y copias valores de una respuesta al siguiente request. Cada vez. Y nadie puede decir rápido de qué APIs depende esa pantalla ni cómo pasan los datos entre ellas.

Luvin elimina esas llamadas manuales. Describes la cadena una sola vez, como un **workflow**: una secuencia de llamadas a APIs en la que cada **paso** puede usar datos de los anteriores. Después Luvin ejecuta toda la cadena por ti y te dice, en palabras simples, si funcionó.

## Ejemplo: la ficha de un Pokémon

El workflow de la Pokédex incluida encadena cuatro llamadas a la PokéAPI pública. Cada flecha es un dato que Luvin conecta por ti:

```text
getPokemon ── id ─────────────▶ getSpecies
           ── mainType ───────▶ getWeakness
           ── firstAbility ───▶ getAbility
```

Escribes un solo valor, `pokemon: pikachu`. Luvin ejecuta los cuatro pasos, pasa cada resultado al siguiente y te dice si la cadena funcionó. Pruébalo en el [inicio rápido](/es/get-started/quick-start/).

## Cómo funciona

<Steps>

1. **Trae tus contratos.** Un contrato es el archivo OpenAPI o AsyncAPI que describe una API. Agrega los contratos de las APIs que participan, o importa tu colección de Postman o Bruno.
2. **Diseña el workflow de forma visual.** Arrastra las operaciones a un lienzo. Luvin conecta solo los datos entre las operaciones, con reglas y sin IA. Por ejemplo, un parámetro `customerId` se conecta con el `id` que devolvió el paso "crear cliente".
3. **Prueba sus escenarios.** Luvin genera **casos** (un caso es una ejecución del workflow con unos inputs dados): el camino feliz, inputs inválidos, llamadas sin credenciales y un caso por cada camino de error. Agrega los tuyos y ejecútalos contra la API real o en **simulación**, donde Luvin responde con los ejemplos del contrato sin llamar a nada. Un caso que pasa en simulación prueba la lógica del workflow, no tu API: cada resultado dice si se ejecutó contra tu API o en simulación.
4. **Comparte la evidencia.** Exporta los resultados como un reporte HTML que cualquiera puede abrir. El workflow se guarda como un archivo [Arazzo](https://spec.openapis.org/arazzo/latest.html) estándar, el formato abierto de la OpenAPI Initiative para secuencias de llamadas a APIs: es tuyo, se lee como YAML, se guarda en git y se puede llevar a otras herramientas de Arazzo. Tu workflow no queda atrapado en Luvin: puedes revisarlo en un pull request, versionarlo junto a tu código y ejecutarlo en un runner de CI que lea Arazzo.

</Steps>

<Aside type="tip" title="¿Sin contratos, o ya tienes archivos Arazzo?">
Si ya tienes archivos Arazzo, ábrelos y funcionan igual. Si no tienes contratos, importa tu colección de Postman o Bruno y arrastra sus requests al lienzo. Consulta [Importar tu trabajo existente](/es/get-started/import/).
</Aside>

## Qué puedes probar

Iniciar sesión y mantener la sesión activa, hacer un pedido, pagar con OAuth 2.0, registrar clientes con datos nuevos, recuperarte de errores. Cada escenario tiene un ejemplo que puedes ejecutar: mira [Qué puedes probar con Luvin](/es/get-started/use-cases/).

## Para quién es

| Eres | Luvin te ayuda a |
|---|---|
| Ingeniero de integración o de QA | Dejar de llamar a cada API a mano. Tienes casos negativos generados, un veredicto claro por caso y cada request en Dev Tools. |
| Parte de un equipo de producto o de partners de APIs | Demostrar que un workflow de varias APIs funciona de punta a punta, con un reporte para compartir. |
| Product manager o rol de negocio | Probar un workflow con tus propios datos en una interfaz simple, sin línea de comandos ni código de pruebas. |
| Diseñador de APIs | Ver cómo se conectan tus APIs y revisar los workflows contra los contratos reales. |

## Alcance y límites

Luvin sirve para diseñar, depurar y demostrar procesos que pasan por varias APIs. No ejecuta integraciones en producción y no es un runner de CI: los workflows que guarda son archivos Arazzo estándar, que puedes llevar a tu pipeline. Consulta [Qué no hace Luvin](/es/reference/faq/#qué-no-hace-luvin).

<Aside type="caution" title="Conoce estos límites antes de planear una prueba">
- **Pasar en Simulación no es pasar contra tu API.** La simulación responde con los ejemplos del contrato. Para probar la API, ejecuta con **API real**.
- **Los pasos de mensajería siempre se simulan.** Los pasos `send` y `receive` de AsyncAPI responden desde el contrato, incluso cuando ejecutas contra la API real. Luvin todavía no se conecta a Kafka, AMQP ni MQTT, así que no puede demostrar una integración asíncrona de punta a punta.

Consulta todas las [limitaciones conocidas](/es/reference/limitations/).
</Aside>
