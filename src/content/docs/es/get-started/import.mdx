No tienes que empezar de cero. Puedes traer archivos Arazzo y contratos, colecciones de Postman o Bruno y un comando copiado como cURL.

Un archivo Arazzo describe un workflow. Un contrato es un archivo OpenAPI o AsyncAPI. Una **colección** es una carpeta de proyecto dentro de un workspace. Consulta el [glosario](/es/reference/glossary/).

## Ejemplo: una colección de Postman

Una colección pequeña exportada de Postman:

```json title="shop-api.postman_collection.json"
{
  "info": {
    "name": "Shop API",
    "schema": "https://schema.getpostman.com/json/collection/v2.1.0/collection.json"
  },
  "item": [
    {
      "name": "Customers",
      "item": [
        {
          "name": "Get customer",
          "request": {
            "method": "GET",
            "url": "{{baseUrl}}/customers/42",
            "header": [{ "key": "Accept", "value": "application/json" }]
          }
        }
      ]
    }
  ]
}
```

Impórtala con un archivo de ambiente que defina `baseUrl` y Luvin crea una colección llamada **Shop API**:

<FileTree>

- shop-api/
  - collection.yaml
  - requests/
    - customers/
      - _folder.request.yaml
      - get-customer.request.yaml
  - environments/
    - sandbox.yaml

</FileTree>

En la barra lateral, **Customers** es una carpeta y **Get customer** un request que envía `GET {{baseUrl}}/customers/42`. Las variables del ambiente de Postman llegan a un ambiente de Luvin. Consulta [Qué hay en disco](/es/workspaces/files/).

![El diálogo Importar colección con una tarjeta para Luvin, otra para Postman y otra para Bruno](/media/es/import-postman.webp)

### Impórtala

Necesitas un workspace abierto. Si no hay ninguno, Luvin dice **Abre o crea un workspace para importar.** Mira [Crear y abrir un workspace](/es/workspaces/create-and-open/).

<Steps>

1. Haz clic en **+** de las pestañas (**Crear o importar**) y luego en **Importar colección (Luvin, Postman o Bruno)**. La misma acción está en el menú ⋯ de **Colecciones** en la barra lateral y en el inicio del workspace, en **Acciones rápidas**.
2. Elige qué importar:

   | Herramienta | Qué elegir |
   |---|---|
   | Luvin | **Elegir .luvin.json**: una colección exportada desde Luvin. Mira [Exportar e importar una colección](/es/workspaces/export-import/) |
   | Postman | **Elegir archivos .json**: la colección exportada (v2.0 o v2.1). Elige también los archivos de ambiente para traer sus variables |
   | Bruno | **Elegir carpeta**: la carpeta de la colección, como Bruno la guarda en git (con archivos `.bru`). O **Elegir .json** para el archivo que exporta Bruno |

   También puedes soltar los archivos sobre el diálogo. Un archivo de Luvin (`.luvin.json`) o un JSON de Postman o Bruno (una colección, un ambiente o una exportación de Bruno) que sueltas en cualquier parte de la ventana también abre este diálogo, aunque el workspace no tenga una colección abierta: la ventana dice **Suelta para importar la colección (Luvin, Postman o Bruno)**. Los demás archivos que sueltas junto con él van a la colección.
3. Lee el resumen. Para cada colección muestra la cantidad de requests, carpetas, ejemplos y ambientes, la autorización de la colección si la hay, y cuántos scripts trae.
4. Cambia el nombre de la colección si quieres. Si el workspace ya tiene una colección con ese nombre, primero elige qué hacer: mira [Cuando la colección ya existe](#cuando-la-colección-ya-existe).
5. Haz clic en **Importar (N requests)**.

</Steps>

Para elegir otros archivos, haz clic en **Elegir otros archivos**.

Luvin abre la colección nueva. Si tiene scripts, Luvin pregunta **¿Confías en esta colección?**: mira [Confiar en una colección](/es/requests/scripts/#confiar-en-una-colección).

![El diálogo ¿Confías en esta colección? sobre la colección importada Shop API, con los botones Ahora no y Confiar](/media/es/scripts-trust-dialog.webp)

### Qué se importa y qué no

| Se importa | No se importa (el resumen lo lista antes de importar) |
|---|---|
| Carpetas y requests, con sus descripciones | Tipos de autorización sin equivalente: esos requests quedan sin autorización |
| Ejemplos guardados | Tipos de body sin equivalente: el body queda vacío |
| Autorización de la colección, la carpeta y el request | Variables con un nombre no válido, y variables desactivadas |
| Ambientes y sus variables | |
| Variables de la colección | |
| Los scripts de la colección, sus carpetas y sus requests, completos (mira más abajo) | |
| Los bloques `vars:post-response` y `assert` de Bruno, como variables y comprobaciones | |

- Una variable marcada como secreta sigue siendo secreta. Bruno no guarda el valor de sus secretos, así que llegan vacíos: escríbelos de nuevo en el ambiente.
- Cada variable llega a su nivel. Las variables de colección de Postman y los `vars:pre-request` de la colección en Bruno pasan a ser [variables de la colección](/es/environments/variable-levels/); las secretas van como secretos a los ambientes de la colección, porque una variable de la colección nunca es secreta. Un archivo de globals de Postman pasa a ser un ambiente global del workspace; si ya hay uno con ese nombre, solo se agregan las variables que le faltan. Los `vars:pre-request` de un request en Bruno pasan a ser variables de ese request.

### Los scripts se traen completos

Los scripts de antes del request y de después de la respuesta llegan tal cual, a la pestaña **Scripts** del mismo nivel: la colección, cada carpeta y cada request. Corren como en Postman o Bruno, en el mismo orden, cuando confías en la colección. La mayoría corre sin cambios. Mira [Scripts](/es/requests/scripts/).

| Desde | Antes del request | Después de la respuesta |
|---|---|---|
| Postman | **Pre-request** | **Post-response** (**Tests**) |
| Bruno | `script:pre-request` | `script:post-response` y luego `tests` |

Los bloques `vars:post-response` y `assert` de Bruno no tienen código: pasan a las pestañas **Variables** y **Comprobaciones** de cada request. Mira [Asserts de Bruno y tests de Postman](/es/requests/checks-from-postman/).

El resumen de cada colección, antes de importar, dice:

- *2 script(s) se traen completos, a la pestaña Scripts de la colección, sus carpetas y sus requests. Corren como en el original cuando confíes en la colección.* Cada nivel cuenta hasta dos: su script de antes del request y el de después de la respuesta.
- *3 variable(s) y assertion(s) de Bruno pasaron a las pestañas Variables y Comprobaciones de cada request.*
- Un aviso cuando algunos scripts usan algo que Luvin no tiene, con los nombres: *Algunos scripts usan algo que Luvin todavía no tiene (pm.vault): corren igual, pero esa parte avisa y falla.* Mira [Lo que no está disponible](/es/requests/scripts-api/#lo-que-no-está-disponible).

![El resumen de la importación de Shop API: 3 requests, 1 carpeta, 1 variable de la colección y 5 scripts que se traen completos a la pestaña Scripts](/media/es/import-scripts-summary.webp)

### Cuando la colección ya existe

Si el workspace ya tiene una colección con el mismo nombre (sin importar mayúsculas), el resumen dice **Ya existe una colección «Shop API» en este workspace.** y ofrece dos opciones:

| Opción | Qué pasa |
|---|---|
| **Importar como copia, con el nombre de arriba** (la que viene marcada) | Una colección nueva. Su nombre lleva `_v1`, `_v2`… para no chocar, por ejemplo `Shop API_v1`. Puedes cambiarlo en el campo del nombre. |
| **Reemplazar el contenido de «Shop API»** | La colección que ya existe se actualiza con lo importado. *Se reemplazan sus requests, carpetas, ambientes, variables, autorización y scripts. Sus workflows, contratos, mocks e historial se quedan. Si trae scripts, vuelve a preguntar si confías en ella.* El campo del nombre queda bloqueado. |

![El resumen de una segunda importación de Shop API: Ya existe una colección «Shop API» en este workspace, con Importar como copia (Shop API_v1) elegido y Reemplazar el contenido de «Shop API»](/media/es/import-duplicate.webp)

Usa **Reemplazar** cuando exportas una versión nueva de la misma colección de Postman: los workflows que armaste sobre ella se quedan.

Las pestañas abiertas son de cada colección. Si cambias a otra colección y vuelves, sus pestañas están como las dejaste, y una copia nunca muestra las pestañas de la original.

<Aside>
Si eliges solo archivos de ambiente, Luvin dice **Eso son solo ambientes: elige también la colección.** Si no encuentra ninguna colección, dice **No encontré una colección de Postman ni de Bruno en lo que elegiste.**
</Aside>

## Archivos Arazzo y contratos

Primero necesitas una colección abierta. Luvin agrega los archivos a ella. Los archivos pueden ser `.yaml`, `.yml` o `.json`.

<Tabs>
<TabItem label="Botón">

<Steps>

1. Abre el inicio del workspace con el ícono de la casa de la barra superior.
2. En **Acciones rápidas**, haz clic en **Importar Arazzo o contratos**.
3. Elige uno o más archivos.

</Steps>

El botón solo aparece cuando hay una colección abierta. Una colección sin Arazzo muestra el mismo consejo.

</TabItem>
<TabItem label="Contrato, desde la barra lateral">

<Steps>

1. En **Contratos**, haz clic en **+** (**Agregar contrato**).
2. Haz clic en **Importar contrato…**.
3. Elige el archivo.

</Steps>

</TabItem>
<TabItem label="Arrastrar y soltar">

<Steps>

1. Arrastra los archivos desde tu explorador de archivos hasta la ventana de Luvin. Dice **Suelta para agregar a «nombre de la colección»**.
2. Suéltalos. Un mensaje dice cuántos se agregaron, por ejemplo **Se agregaron 3 archivo(s) a la colección**.

</Steps>

Si no hay una colección que los reciba, el mensaje es **Abre o crea una colección para agregarle archivos**. Los otros tipos de archivo se omiten y Luvin dice cuántos.

</TabItem>
</Tabs>

<Aside type="tip">
Si un contrato apunta a otros archivos con `$ref`, agrégalos también. Suelta juntos el Arazzo, sus contratos y los archivos de `$ref`. Cuando falta alguno, el contrato muestra ✕ en la barra lateral. Consulta [Solución de problemas](/es/get-started/troubleshooting/).
</Aside>

## Un comando cURL

Un comando cURL es un request escrito como texto, como los que Chrome, Postman o la documentación de una API te dejan copiar.

```bash
curl -X POST 'https://api.shop.test/customers' \
  -H 'Content-Type: application/json' \
  --data-raw '{"name":"Ana"}'
```

![El diálogo Importar desde cURL con un comando pegado](/media/es/import-curl.webp)

<Steps>

1. Haz clic en **+** de las pestañas (**Crear o importar**) y luego en **Nuevo request**.
2. Haz clic en **Importar desde cURL**.
3. Pega el comando. Se convierten el método, la URL, los headers, la autorización y el body.
4. Haz clic en **Importar**.

</Steps>

El comando debe empezar con `curl` e incluir una URL. Si no, Luvin dice que no parece un comando cURL válido. Los menús de requests de la barra lateral también ofrecen **Importar desde cURL**. Para copiar un paso como cURL, consulta [cURL](/es/requests/curl/).

## Abrir archivos sin workspace

Para probar algo rápido, abre archivos sin workspace.

<Steps>

1. En la pantalla de bienvenida, haz clic en **Abrir archivos sin workspace**, abajo. Luvin abre un selector de carpetas.
2. Elige tus contratos, tus archivos Arazzo y los archivos a los que apuntan sus `$ref`. También puedes soltarlos sobre la pantalla de bienvenida.

</Steps>

Si cierras la bienvenida con **Prefiero explorar por mi cuenta**, la pantalla vacía ofrece **Abrir archivos** y **Abrir carpeta**. De una carpeta se cargan todos los archivos YAML y JSON que tenga, con sus subcarpetas. Si tiene muchos archivos, solo se cargan los primeros 300, y Luvin lo avisa.
