Un reporte es una copia de tus resultados en un archivo. Úsalo para mostrar que un workflow funciona, para enviar una falla a quien construye la API, o para guardar un registro de una ejecución. La persona que lo recibe no necesita Luvin.

## Ejemplo: reporte de una ejecución de Pokemon card

<Tabs>

  </TabItem>

El archivo `reporte-<título>-<fecha>.json` tiene los mismos resultados para otra herramienta. Los nombres de sus campos están en inglés sea cual sea el idioma de la app.

    { "id": "…", "title": "…", "origin": "arazzo", "inputs": {}, "expected": "…",
      "verdict": "passed", "explanation": "…", "steps": [], "outputs": {} }

## Exporta el reporte HTML

<Steps>
1. Ejecuta los casos. Mira [Ejecutar](/es/test/run/).
2. En el encabezado de los resultados, pulsa **Reporte**.
3. Luvin descarga un archivo llamado `reporte-<título>-<fecha>.html`.
</Steps>

**Reporte** se oculta mientras una ejecución está en curso y mientras los resultados están plegados.

El reporte incluye los últimos resultados de cada workflow que hayas ejecutado, no solo el que ves en pantalla. Está escrito en el idioma que usa la app.

## Qué contiene el reporte

| Parte | Qué muestra |
|---|---|
| Encabezado | El título, la fecha, el archivo Arazzo, cuántos workflows y casos cubre, y la duración total. |
| Resumen en palabras simples | La misma frase que en los resultados, por ejemplo *El camino feliz funciona, con puntos para revisar.* |
| Contadores | **Pasaron**, **No pasaron**, **Advertencias**, **No concluyentes** y **Simulados**. |
| **Ambiente** | El nombre del ambiente y la URL base de cada API. |
| **Resumen de casos** | Una tabla con cada caso: su tipo, si se simuló o corrió contra la API real, sus inputs y su veredicto. Haz clic en un caso para saltar a su detalle. |
| **Detalle por caso** | Qué se esperaba, el resultado, los **Valores enviados**, y cada paso con su petición, respuesta, criterios, comprobación del contrato y outputs. |

![El reporte de un workflow de tienda: el resumen, los contadores por veredicto, el ambiente y el comienzo del resumen de casos](/media/es/test-report.webp)

![La tabla Resumen de casos: cada caso con su tipo, si se ejecutó contra la API real o simulado, sus inputs y su veredicto](/media/es/test-report-cases.webp)

Los pasos están cerrados al principio, salvo los que fallaron. Los botones de arriba son **Expandir todo**, **Contraer todo** e **Imprimir / guardar como PDF**.

## Un archivo, nada más

El reporte es un único archivo HTML con sus estilos adentro. No necesita conexión a internet ni otro archivo. Quien lo recibe lo abre en cualquier navegador.

Para enviar un PDF, abre el reporte y pulsa **Imprimir / guardar como PDF**. Cada paso se expande antes de imprimir.

## Los secretos van ocultos

El reporte está hecho para compartirse:

- Los secretos y credenciales del ambiente aparecen como `••••`.
- Los valores de campos y headers cuyo nombre parece sensible (`token`, `password`, `secret`, `authorization`, `api key`) también se ocultan.
- El pie recuerda al lector que los valores de las credenciales están ocultos y que los casos simulados usan los ejemplos del contrato, no la API real.

<Aside type="caution">
La ocultación cubre los secretos y los campos con nombres sensibles. Otros datos de los requests y las respuestas, como nombres o emails de clientes de prueba, quedan en el reporte tal como se enviaron y se recibieron. Léelo antes de enviarlo fuera de tu equipo.
</Aside>

## Exporta como JSON

<Steps>
1. En el encabezado de los resultados, pulsa **JSON**.
2. Se descarga un archivo llamado `reporte-<título>-<fecha>.json`.
</Steps>

El JSON tiene los mismos resultados en una forma que otra herramienta puede leer: cuándo se generó, el ambiente y, para cada caso, su id, título, inputs, resultado esperado, veredicto, explicación, pasos y outputs. Las credenciales se ocultan de la misma manera.

Los nombres de los campos están en inglés sea cual sea el idioma de la app, por ejemplo `cases`, `verdict` y `steps`, así una herramienta lee todos los reportes igual. El veredicto es uno de `passed`, `failed`, `warning` o `inconclusive`. `origin` dice de dónde salió el caso: `arazzo` (los criterios de éxito), `response` (uno por respuesta documentada), `schema` (inputs inválidos o faltantes), `security` (sin credenciales) o `data` (tus casos con datos propios).

## Comparte con alguien que no tiene Luvin

| Necesita | Envía |
|---|---|
| Leer qué pasó | El reporte HTML, o su PDF |
| Reproducir un request | El texto de **Copiar como cURL** en el paso. Mira [Lee el resultado de un paso](/es/test/step-results/). |
| Procesar los resultados con una herramienta | El archivo JSON |
| Ejecutar el workflow por su cuenta | El archivo Arazzo y sus contratos. Mira [Archivos de un workspace](/es/workspaces/files/). |
