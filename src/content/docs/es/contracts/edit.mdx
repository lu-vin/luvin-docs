Haz clic en un contrato en la barra lateral y Luvin lo abre en un editor. A la izquierda editas el YAML. A la derecha ves el contrato como una página legible, que se actualiza mientras escribes. Los workflows que usan el contrato se analizan de nuevo con cada cambio, así que ves el efecto de una edición antes de ejecutar nada.

![Un contrato abierto: el editor de YAML a la izquierda y la vista previa de Swagger UI a la derecha](/media/es/contract.webp)

## Ejemplo: agregar una operación al contrato de la PokéAPI

Quieres un paso que consulte el color de un Pokémon. Abre `pokeapi` desde la lista **Contratos** y agrega una operación dentro de `paths`:

<Tabs>
<TabItem label="Antes">

```yaml title="pokeapi.openapi.yaml" {6}
  /pokemon-color/{idOrName}:
    get:
      operationId: getPokemonColor
      summary: Consulta un color
      parameters:
        - { name: idOrName, in: path, schema: { type: string } }
      responses:
        '200':
          description: El color
```

Sobre la vista previa aparece **Errores (1)**: **Error** · **Línea 6** · *El parámetro de ruta «idOrName» debe tener required: true.*

</TabItem>
<TabItem label="Después">

```yaml title="pokeapi.openapi.yaml" {6}
  /pokemon-color/{idOrName}:
    get:
      operationId: getPokemonColor
      summary: Consulta un color
      parameters:
        - { name: idOrName, in: path, required: true, schema: { type: string } }
      responses:
        '200':
          description: El color
```

El panel desaparece. Swagger UI muestra `GET /pokemon-color/{idOrName}`, y **＋ Paso**, en la pestaña **Diseño**, la lista en el grupo `pokeapi`.

</TabItem>
</Tabs>

El número de línea apunta al parámetro. Haz clic en el mensaje y el editor salta a él.

## La barra superior

| Elemento | Qué muestra o hace |
|---|---|
| Nombre del archivo | El archivo del contrato, por ejemplo `pokeapi.openapi.yaml`. |
| Tipo y versión | Una insignia como **OpenAPI 3.0.3**, **Swagger 2.0** o **AsyncAPI 3.0.0**. Un archivo de schemas no tiene insignia. |
| **Solo lectura** | El archivo no es parte de tu colección, así que no puedes cambiarlo. Mira [Hacer una copia local](#hacer-una-copia-local). |
| **$ref: archivo** | Un botón por cada archivo de la colección que este contrato menciona, como un archivo de schemas. Haz clic para abrir ese archivo. |
| Estado del guardado | En un workspace, **Guardado automáticamente**. Fuera de un workspace, **Cambios sin guardar en un archivo** mientras tienes cambios sin guardar. |
| **Generar requests** | Solo OpenAPI. Abre **Generar requests de «nombre»**. Mira [Generar requests desde un contrato](/es/requests/generate-from-contract/). |
| **Hacer copia local** | Solo en un contrato de **Solo lectura**. |
| **Descartar cambios** y **Guardar archivo** | Solo fuera de un workspace. Mira [Guardar los cambios](#guardar-los-cambios). |

## El editor

El editor colorea el YAML, numera las líneas y marca cada problema en el margen. Luvin lee el texto como un tercio de segundo después de que dejas de escribir. Entonces:

1. revisa el YAML y el contrato, y lista los problemas sobre la vista previa,
2. actualiza la vista previa,
3. carga la nueva versión para los workflows que usan el contrato, y los analiza de nuevo.

Un problema aparece en dos lugares: subrayado en el YAML, con una marca en el margen, y en el panel sobre la vista previa. El panel se llama **Errores (n)** cuando hay al menos un error, y **Advertencias (n)** cuando solo hay advertencias o información. Cada línea muestra el nivel (**Error**, **Advertencia** o **Info**), la línea (**Línea 12**) y el mensaje. Haz clic en una línea para saltar a ella. **Ocultar** y **Mostrar** pliegan el panel.

Cada mensaje, qué significa y cómo corregirlo está en [Errores y advertencias del contrato](/es/contracts/lint-errors/).

<Aside type="note" title="Mientras el YAML no se puede leer">
Un error de sintaxis del YAML, como una sangría equivocada, aparece como error con su línea. Hasta que lo corrijas, la vista previa sigue mostrando la última versión que se pudo leer, y los workflows también la siguen usando. Nada se rompe mientras escribes.
</Aside>

## La vista previa

| Archivo | Vista previa |
|---|---|
| OpenAPI | La **Swagger UI** oficial. Puedes probar una operación desde ella. Mira [Probar una operación](/es/contracts/try-it-out/). |
| AsyncAPI | La vista previa propia de Luvin, con operaciones **SEND** y **RECEIVE**. Mira [Contratos AsyncAPI](/es/contracts/asyncapi/). |
| Un archivo de schemas que otros archivos referencian | Una sección **Schemas**, con cada schema como un árbol que puedes desplegar. |
| Un archivo que no se puede mostrar | *No se puede mostrar la documentación de este archivo.* |

Cuando un archivo de workflows nombra el contrato, la vista previa lo muestra completo: las partes que vienen de otros archivos con `$ref` ya están unidas. Si Swagger UI no logra iniciar, ves *No se pudo cargar Swagger UI:* y el motivo.

### Los servidores en Swagger UI

En la parte de arriba de Swagger UI, **Servers** lista primero la URL base del ambiente activo, con el nombre *Ambiente «nombre» (Luvin)*, y después los servidores del contrato. Las llamadas de **Try it out** van al servidor que elijas ahí.

Esto solo pasa cuando un archivo de workflows nombra el contrato (✓ en la lista). Para un contrato ○, **Servers** lista solo los servidores del contrato, y las credenciales del ambiente no se completan. Mira [Servidores y credenciales](/es/contracts/servers-and-credentials/).

## Cuando un cambio afecta a un workflow

Sobre la vista previa, una barra muestra el efecto de tu edición en los workflows que usan el contrato:

- *N workflow(s) usan este contrato · sin problemas nuevos*
- *Este cambio rompe N workflow(s).*

Haz clic en ella para ver cada workflow y los problemas nuevos, y haz clic en un problema para abrir el paso. La barra no aparece cuando ningún workflow usa el contrato. Mira [Cuando un cambio rompe un workflow](/es/contracts/impact/).

## Guardar los cambios

| Dónde trabajas | Cómo se guarda |
|---|---|
| Un workspace | Cada cambio se escribe solo en el archivo de la carpeta de la colección. La barra dice **Guardado automáticamente**. |
| Fuera de un workspace (archivos abiertos sin workspace) | Luvin guarda tu texto en la sesión. Pulsa **Guardar archivo** para escribirlo. **Descartar cambios** vuelve al texto con el que abriste. |

Guardar no ejecuta nada y no cambia los archivos de workflows. Si tu cambio rompe un workflow, corrige el contrato o ajusta el workflow después.

## Hacer una copia local

Un contrato que se descargó de una URL, o que adjuntaste a una fila con **Adjuntar**, se abre como **Solo lectura**. El archivo no es parte de tu colección, así que un cambio no tendría dónde guardarse. La excepción: en un workspace, un archivo adjuntado a una fila cuya `url` es una ruta dentro de la colección se guarda ahí, y puedes editarlo como cualquier otro. Mira [Contratos remotos y referencias](/es/contracts/remote-and-refs/#adjuntar-un-archivo-en-su-lugar).

<Steps>

1. Abre el contrato.
2. Haz clic en **Hacer copia local**. El tooltip dice *Este contrato viene de una URL o se adjuntó: crea una copia en la colección para poder editarla.*

</Steps>

Luvin agrega el contrato como un archivo de la colección, con el mismo nombre. La insignia **Solo lectura** desaparece y puedes editarlo. Los workflows siguen usándolo, ahora desde la copia.

<Aside type="note">
Desde ese momento, la copia y el original son independientes. Las ediciones de la copia no cambian el original, y los cambios publicados en la URL no llegan a tu copia. Para tomar una versión más nueva, importa el archivo nuevo: un archivo con el mismo nombre reemplaza la copia.
</Aside>

El texto de un contrato descargado es la lectura que hace Luvin del archivo, así que puede no tener los comentarios ni el formato original. Un archivo adjuntado conserva su texto tal como era.
