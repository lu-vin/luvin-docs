Empieza por mirar qué se envió de verdad: abre **Request enviado** en la respuesta de un request, o el paso en los resultados de un workflow. La mayoría de los problemas se ven ahí.

## La API responde 401

`401 Unauthorized` significa que la API no aceptó quién eres.

| Revisa | Qué hacer |
|---|---|
| No se envió nada | **Request enviado** dice *No se envió ninguna Authorization. Revisa la pestaña Autorización del request o de la colección.* Elige un **Tipo**, o configura la autorización de la colección. |
| El request hereda y la colección no tiene ninguna | La pestaña dice *La colección no tiene autorización configurada, así que este request va sin autorización.* Configúrala en la colección. |
| Una variable está vacía o no existe | Revisa el valor en el ambiente activo. Un `{{nombre}}` en rojo no existe. |
| Escribiste un header `Authorization` | El tuyo gana sobre Basic, Bearer y OAuth 2.0. Borra la fila en **Headers**. |
| Ambiente equivocado | Las credenciales son por ambiente. Revisa cuál está activo. |
| En un workflow | Abre la pestaña **Autorización**: **Se usa** dice de dónde viene. Con **Del contrato**, revisa **Credenciales** en el ambiente. |

## La API responde 403

`403 Forbidden` significa que la API sabe quién eres pero no lo permite.

- Revisa **Scope** y **Audience** de OAuth 2.0: puede que al token le falte un permiso.
- Con **AWS Sig v4** y *signature does not match*, revisa **Región**, **Servicio** y el reloj de tu computadora.
- Comprueba en la propia API que el usuario o la clave tienen acceso a ese recurso.

## El token venció

- Con **OAuth 2.0**, Luvin renueva el token solo cuando vence (con el refresh token, o pidiendo uno nuevo). Pulsa **Borrar token** y **Obtener token nuevo** para forzarlo.
- Con **Authorization Code** y sin refresh token, inicia sesión de nuevo: **Obtener token nuevo**, o **Iniciar sesión** en un workflow.
- Con un **Bearer Token** escrito a mano, Luvin no puede renovarlo. Pega uno nuevo, o usa [OAuth 2.0](/es/authorization/oauth2/) o un [paso de login](/es/recipes/login-token/).
- Los tokens se guardan solo en memoria. Al cerrar la colección o cambiar de ambiente desaparecen, y el próximo envío pide uno nuevo.

## No se puede obtener el token

*No se pudo obtener el token:* va seguido del motivo del propio proveedor. Revisa **URL del token**, **Client ID**, **Client Secret** y **Enviar credenciales del cliente en** (**Basic Auth header** o **Body**: usa el que espera tu proveedor).

## La ventana de inicio de sesión no se abre

- **URL de callback** es obligatoria. Sin ella ves *Falta la URL de callback.* Completa también **URL de autorización**.
- Si cerraste la ventana: *Se cerró la ventana de autorización antes de terminar.* Empieza de nuevo.
- *El proveedor no autorizó:* seguido de un motivo significa que la persona no aprobó, o que el callback o el cliente no coinciden con lo registrado en el proveedor.

## Nada funciona

<Aside type="tip">
Copia el request como cURL (los secretos aparecen como `<secret>`, complétalos) y ejecútalo en una terminal. Si también falla allí, el problema está en las credenciales o en la API, no en Luvin. Mira [Copiar como cURL](/es/requests/curl/).
</Aside>
