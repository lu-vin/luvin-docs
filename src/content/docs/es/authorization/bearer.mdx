Usa **Bearer Token** cuando ya tienes un token y la API dice "envía un bearer token". Para obtener un token de un servidor de autorización, usa [OAuth 2.0](/es/authorization/oauth2/). Para usar un token que devuelve un paso de login, mira [Pasa el token del login a los pasos siguientes](/es/authorization/token-from-login/).

## Ejemplo

Request `GET https://httpbin.org/bearer`.

**Tipo** `Bearer Token`, **Token** `abc123`, **Prefijo del header** `Bearer`. Luvin envía:

```text
Authorization: Bearer abc123
```

La respuesta es `200`:

```json
{
  "authenticated": true,
  "token": "abc123"
}
```

Sin el token, el mismo request responde `401`.

## Campos

| Campo | Qué escribir |
|---|---|
| **Token** | El token. Es un campo secreto. |
| **Prefijo del header** | La palabra antes del token. `Bearer` mientras no lo cambies. |

Otro prefijo, por ejemplo `Token`, da `Authorization: Token abc123`. Si escribes un prefijo y luego lo borras, solo se envía el token.

## Reglas

- Si escribiste un header `Authorization` en **Headers**, el tuyo gana.
- Con **Token** vacío, no se envía nada.
- Funciona en requests, en la colección y en un workflow.

## Secretos

**Token** es un secreto. Escrito tal cual se guarda cifrado en tu equipo. Escribe `{{token}}` y guarda el valor en el ambiente para compartir la configuración. Mira [Secretos](/es/authorization/secrets/).
