Un ambiente abierto tiene cuatro secciones: **URLs base**, **Credenciales**, **Variables** y **Secretos**. Las variables y los secretos son valores con nombre que usas como `{{nombre}}` en cualquier campo. La diferencia es dónde vive el valor: una variable se escribe en el archivo del ambiente, un secreto se guarda cifrado en tu equipo.

## Ejemplo: el ambiente sandbox de PayPal

El ejemplo de PayPal se abre con el ambiente `Sandbox`, una variable `clientId` y un secreto `clientSecret`, los dos vacíos. Después de pegar los dos valores de tu app del sandbox y elegir una etiqueta amarilla, Luvin escribe este archivo en la carpeta `environments/` de la colección:

```yaml title="environments/sandbox.yaml"
# Luvin environment. Secret and credential values are not stored here: they live encrypted on each computer.
name: Sandbox
color: yellow
servers:
  paypal: https://api-m.sandbox.paypal.com
variables:
  clientId: mi-client-id-del-sandbox
secrets:
  - clientSecret
id: 6c1f2d9e-4b7a-4e0f-9a3c-2d8b5e7f1a40
```

La autorización de los workflows del ejemplo usa los dos valores:

| Escribes | Luvin envía |
|---|---|
| Client ID `{{clientId}}` | `mi-client-id-del-sandbox` |
| Client Secret `{{clientSecret}}` | El valor del secreto. En resultados, reportes y Dev Tools aparece como `••••` |
| `{{paypal}}/v2/checkout/orders` en un request | `https://api-m.sandbox.paypal.com/v2/checkout/orders` |

El archivo lista el nombre `clientSecret` pero nunca su valor. La primera línea es un comentario que la app escribe en inglés, sea cual sea el idioma de la interfaz. El `id` une el ambiente con sus secretos en cada equipo. Mira [Archivos de ambiente y equipos](/es/environments/files-and-teams/).

## Variables

Una variable es un valor con nombre que cambia según el ambiente: un ID de cliente, un código de partner, un usuario de prueba. En **Variables**, la pestaña explica: *Valores que cambian según el ambiente (un ID de cliente, un código de partner…). Úsalas como `{{clientId}}` en los inputs, en los datos de cada caso, en las URLs base y en las credenciales.*

<Steps>

1. Abre el ambiente.
2. En **Variables**, haz clic en **+ Agregar variable**.
3. Escribe el **Nombre** y el **Valor**.
4. Úsala como `{{clientId}}` en cualquier campo. Mira [Usar variables](/es/environments/use-variables/).

</Steps>

Para eliminar una, haz clic en el ícono de papelera al final de su fila (**Eliminar**). El título de la sección dice cuántas variables tiene el ambiente.

### Reglas de los nombres

| El nombre | Qué ves |
|---|---|
| Tiene un espacio, empieza con un número o usa otros símbolos | En rojo: *Usa letras, números, _ . o - (sin espacios) y empieza con una letra o _.* |
| Ya lo usa otra variable u otro secreto de este ambiente | En rojo: *Ya hay otra variable con este nombre.* |
| Es el nombre de un generador de Luvin, como `email` o `uuid` | Un aviso: *Tapa al generador `{{email}}`: se usará el valor de la variable.* |

Un nombre con error se conserva, para que lo corrijas, pero `{{nombre}}` no lo usa hasta que sea válido. Ejemplos válidos: `clientId`, `codigo_partner`, `user.email`, `api-version`.

## Secretos

Un secreto es una variable para claves, tokens y contraseñas. Se usa igual, como `{{apiKey}}`. En **Secretos**, la pestaña explica: *Como las variables (`{{apiKey}}`), pero para claves y tokens: se guardan cifrados en este equipo, nunca en los archivos del workspace, y en resultados y reportes aparecen como ••••.*

<Steps>

1. En **Secretos**, haz clic en **+ Agregar secreto**.
2. Escribe el **Nombre** y el **Valor**. El valor queda oculto mientras escribes.
3. Haz clic en el ojo para verlo (**Mostrar el valor**). Vuelve a hacer clic para ocultarlo (**Ocultar el valor**).

</Steps>

Los secretos siguen las mismas reglas de nombres que las variables y comparten con ellas la lista de nombres: una variable y un secreto no pueden llamarse igual. No hay un interruptor para convertir una variable en secreto. Elimina la variable y agrega un secreto con el mismo nombre.

## Dónde se guarda cada valor

| Valor | Dónde vive |
|---|---|
| Variable | En el archivo del ambiente, `environments/<nombre>.yaml`, tal como lo escribiste. Va a git con el workspace. |
| Nombre de un secreto | En el archivo del ambiente, en `secrets`. |
| Valor de un secreto | Cifrado en este equipo, con el llavero del sistema operativo. |
| Sin llavero disponible | Los valores de los secretos no se guardan. Los vuelves a escribir después de reabrir la colección. |
| Sin workspace abierto (un ejemplo o archivos sueltos) | Los valores de los secretos no se guardan. Luvin recuerda solo los nombres. |

Las credenciales se guardan como los secretos. Los valores guardados por los requests (**Guardadas ahora**) nunca se escriben en ninguna parte: quedan en memoria mientras la colección está abierta, y Luvin los borra al cambiar de ambiente.

## Dónde se tapan los valores secretos

Luvin reemplaza cada valor secreto, y cada credencial, por `••••` dondequiera que aparecería:

- En los resultados de los workflows y en los reportes exportados, también en los inputs que usó un caso.
- En **Request enviado** de un request suelto, y en **Dev Tools**.
- En el historial: los requests y las ejecuciones se guardan con los secretos tapados.
- En un comando cURL copiado, donde el valor se escribe como `<secret>`.

Un secreto se encuentra también cuando viaja codificado en una URL, por ejemplo con `/` o `+` convertidos en `%2F` o `%2B`.

<Aside type="caution" title="Lo que el tapado no cubre">
Los valores de menos de cuatro caracteres no se tapan, porque ocultarlos taparía letras sueltas en cualquier texto. No uses secretos tan cortos. Una contraseña que escribes directamente en un body o en un input no es un secreto y no se tapa: ponla en un secreto y escribe `{{password}}`.
</Aside>

## ¿Variable o secreto?

| El valor es… | Usa |
|---|---|
| El mismo para todo el equipo, e inofensivo si alguien lo lee: un ID de cliente, una región, un cliente de prueba | Una variable. Viaja con el workspace. |
| Personal o peligroso si se filtra: una contraseña, un client secret, una API key, un token | Un secreto. Cada persona escribe el suyo. |
| Un token que devuelve un request de login | Ninguno. Guárdalo desde la respuesta. Mira [Guarda valores de una respuesta](/es/requests/save-variables/). |

Una variable no tiene que vivir en un ambiente. Si su valor es igual en todos los ambientes, hazla variable de la colección; si solo la usa un request, variable del request; si la comparten todas las colecciones del workspace, ponla en un ambiente global. Consulta [Dónde vive una variable](/es/environments/variable-levels/).

## URLs base y credenciales

Las otras dos secciones del ambiente tienen su propia página:

- **URLs base**: una por contrato, más las tuyas para los requests sueltos. Mira [URLs base](/es/environments/base-urls/).
- **Credenciales**: los valores que piden los esquemas de seguridad de los contratos. Mira [Credenciales](/es/environments/credentials/).
