The collection's authorization is the one authorization that every request set to **Inherit from collection** uses. Set it once, change it in one place.

![The Authorization tab of the collection with Bearer Token selected](/media/en/collection-auth.webp)

## Example

Your shop API takes a bearer token for every call.

<Steps>

1. Click the name of the collection in the sidebar. The collection overview opens.
2. Click the **Authorization** tab, open **Type** and choose **Bearer Token**.
3. In **Token**, write `{{token}}`. Leave **Header prefix** on `Bearer`.
4. Open a request that is on **Inherit from collection**, click **Send**, then open **Sent request**. The `Authorization` header is there, shortened.

</Steps>

The tab says: *For standalone requests: used by those set to “Inherit from collection”. Workflows pick theirs per API, in their Authorization tab.*

## Types

The tab offers the same types as a request, except **Inherit from collection**: **AWS Sig v4**, **Basic Auth**, **Bearer Token**, **Digest Auth**, **NTLM Auth**, **OAuth 1.0**, **OAuth 2.0**, **WSSE Auth**, **API Key**, **Akamai EdgeGrid** and **No Auth**. Each is explained in its own page, for example [Bearer Token](/authorization/bearer/).

A new collection starts with **No Auth**, so inheriting requests go without authorization: *Requests that inherit from the collection are sent without authorization.*

## Which requests use it

- Every HTTP and GraphQL request whose **Type** is **Inherit from collection**. That is the default for new requests of those kinds.
- A request shows it: *Uses the collection’s authorization: Bearer Token.*
- In **Headers**, the `Authorization` row reads *Inherited from the collection · Bearer Token*.
- Workflows do not use it, unless an API is set to **Inherit from collection** in the workflow's tab.

## Make a request opt out

<Steps>

1. Open the request and click **Authorization**.
2. In **Type**, choose **No Auth** (send nothing) or another type (use its own).

</Steps>

## OAuth 2.0 in the collection

With **OAuth 2.0**, the tab has **Get new token** and **Clear token**. All inheriting requests **share one token**. Changing the collection's authorization discards it. See [OAuth 2.0](/authorization/oauth2/).

## Where it is saved

In `collection.yaml`, in the folder of the collection, under `auth`. Secrets typed as-is are left out of the file:

```yaml title="collection.yaml" {3-6}
version: 1
name: Shop
auth:
  type: bearer
  token: "{{token}}"
  prefix: Bearer
```

With **No Auth**, the `auth` key is not written. A secret typed as-is, for example `abc123` in **Token**, is stored encrypted on your computer and the file keeps only `type: bearer`. Your teammates will not receive it. Use `{{token}}` and fill the value in each environment. See [Secrets](/authorization/secrets/).

<Aside type="note">
Set the authorization in the app. Do not edit it by hand in `collection.yaml`.
</Aside>
