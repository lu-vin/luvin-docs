Start by looking at what was really sent: open **Sent request** in the response of a request, or the step in the results of a workflow. Most problems show there.

## The API answers 401

`401 Unauthorized` means the API did not accept who you are.

| Check | What to do |
|---|---|
| Nothing was sent | **Sent request** says *No Authorization was sent. Check the Authorization tab of the request or of the collection.* Choose a **Type**, or set the collection's authorization. |
| The request inherits and the collection has none | The tab says *The collection has no authorization set up, so this request goes without one.* Set it in the collection. |
| A variable is empty or missing | Check the value in the active environment. A `{{name}}` in red does not exist. |
| You wrote an `Authorization` header | Yours wins over Basic, Bearer and OAuth 2.0. Delete the row in **Headers**. |
| Wrong environment | Credentials are per environment. Check which one is active. |
| In a workflow | Open the **Authorization** tab: **In use** tells where it comes from. With **From the contract**, check **Credentials** in the environment. |
| A step of a workflow, but the request alone works | In **Design**, click the step and open its **Authorization** tab: it says what the step uses. A card marked **🔑 no authorization** has none. If the API has a login, give its token to the next steps. See [Pass the login token to the next steps](/authorization/token-from-login/). |

## The API answers 403

`403 Forbidden` means the API knows who you are but does not allow it.

- Check the **Scope** and **Audience** of OAuth 2.0: the token may lack permission.
- For **AWS Sig v4** with *signature does not match*, check **Region**, **Service** and your computer's clock.
- Check that the user or key has access to that resource in the API itself.

## The token expired

- With **OAuth 2.0**, Luvin renews the token by itself when it expires (with the refresh token, or by asking for a new one). Press **Clear token** and **Get new token** to force it.
- With **Authorization Code** and no refresh token, sign in again: **Get new token**, or **Sign in** in a workflow.
- With **Bearer Token** typed by hand, Luvin cannot renew it. Paste a new one, or use [OAuth 2.0](/authorization/oauth2/) or a [login step](/authorization/token-from-login/).
- Tokens are kept in memory only. When you close the collection or switch environments they are gone, and the next send asks for a new one.

## The token cannot be fetched

*The token couldn’t be fetched:* is followed by the provider's own reason. Check **Access token URL**, **Client ID**, **Client Secret** and **Send client credentials in** (**Basic Auth header** or **Body**: use the one your provider expects).

## The sign-in window does not open

- **Callback URL** is required. Without it you see *The callback URL is missing.* Fill in **Authorization URL** too.
- If you closed the window: *The authorization window was closed before finishing.* Start again.
- *The provider didn’t authorize:* followed by a reason means the person did not approve, or the callback or client does not match what is registered with the provider.

## Nothing helps

<Aside type="tip">
Copy the request as cURL (secrets show as `<secret>`, so fill them in) and run it in a terminal. If it fails there too, the problem is in the credentials or in the API, not in Luvin. See [Copy as cURL](/requests/curl/).
</Aside>
