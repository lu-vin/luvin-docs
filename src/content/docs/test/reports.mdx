A report is a copy of your results in a file. Use it to show that a workflow works, to send a failure to whoever builds the API, or to keep a record of a run. The person who receives it does not need Luvin.

## Export the HTML report

<Steps>
1. Run the cases. See [Run](/test/run/).
2. In the header of the results, press **Report**.
3. Luvin downloads a file named `report-<title>-<date>.html`.
</Steps>

**Report** is hidden while a run is in progress and while the results are collapsed.

The report includes the latest results of every workflow you have run, not only the one on screen. It is written in the language the app is using.

## What the report contains

| Part | What it shows |
|---|---|
| Header | The title, the date, the Arazzo file, how many workflows and cases it covers, and the total duration. |
| Summary in plain words | The same sentence as in the results, for example *The happy path works, with points to review.* |
| Counters | **Passed**, **Failed**, **Warnings**, **Inconclusive** and **Simulated**. |
| **Environment** | The name of the environment and the base URL of each API. |
| **Case summary** | A table with every case: its type, whether it was simulated or ran against the real API, its inputs and its verdict. Click a case to jump to its detail. |
| **Details per case** | What was expected, the result, the **Values sent**, and every step with its request, response, criteria, contract check and outputs. |

![The report of a shop workflow: the summary, the counters by verdict, the environment and the start of the case summary](/media/en/test-report.webp)

![The Case summary table: each case with its type, whether it ran against the real API or simulated, its inputs and its verdict](/media/en/test-report-cases.webp)

Steps are closed at first, except the ones that failed. The buttons at the top are **Expand all**, **Collapse all** and **Print / save as PDF**.

## One file, nothing else

The report is a single HTML file with its styles inside. It needs no internet connection and no other file. Whoever receives it opens it in any browser.

To send a PDF instead, open the report and press **Print / save as PDF**. Every step is expanded before printing.

## Secrets are masked

The report is made to be shared:

- The secrets and credentials of the environment appear as `••••`.
- Values in fields and headers whose name looks sensitive (`token`, `password`, `secret`, `authorization`, `api key`) are masked too.
- The footer reminds the reader that credential values are hidden and that simulated cases use the contract examples, not the real API.

<Aside type="caution">
Masking covers secrets and fields with sensitive names. Other data in the requests and responses, such as names or emails of test customers, is in the report as it was sent and received. Read it before you send it outside your team.
</Aside>

## Export as JSON

<Steps>
1. In the header of the results, press **JSON**.
2. A file named `report-<title>-<date>.json` is downloaded.
</Steps>

The JSON has the same results in a form another tool can read: when it was generated, the environment, and for each case its id, title, inputs, expected result, verdict, explanation, steps and outputs. Credentials are masked in the same way.

The field names are in English whatever language the app is in, for example `cases`, `verdict` and `steps`, so a tool reads every report the same way. The verdict is one of `passed`, `failed`, `warning` or `inconclusive`. `origin` says where the case came from: `arazzo` (the success criteria), `response` (one per documented response), `schema` (invalid or missing inputs), `security` (no credentials) or `data` (your own data cases).

## Share with someone who does not have Luvin

| They need to | Send |
|---|---|
| Read what happened | The HTML report, or its PDF |
| Reproduce one request | The text from **Copy as cURL** in the step. See [Read a step result](/test/step-results/). |
| Process the results with a tool | The JSON file |
| Run the workflow themselves | The Arazzo file and its contracts. See [Files of a workspace](/workspaces/files/). |
