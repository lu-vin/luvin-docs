Running a workflow runs its selected cases, one after another, and gives each one a verdict. You choose where they run, against which environment, and press **Run**.

<video controls muted playsinline preload="metadata" poster="/media/en/run-cases.webp" src="/media/en/run-cases.mp4"></video>

## Example: run Pokemon card

The Pokédex example needs no credentials, so you can run it right away.

<Steps>
1. Open **Pokemon card** and click the **Cases** tab. Its two cases are ticked.
2. In the run bar, choose **Simulation**. The button reads **Run 2 cases**.
3. Press **Run**. The results open at the bottom: *Running case 2 of 2*, then a verdict for each case.
4. Switch to **Real API** and press **Run** again. The run pauses to ask you to choose from a list. See [Choose an item from a list](/test/lists/).
</Steps>

Run from the **Design** tab and the result is drawn on the canvas instead: each step card says how it ended, and a bar at the bottom lists the cases. See [Results on the canvas](/test/run-on-canvas/).

## The run bar

The run bar is at the top of an open workflow, above its tabs. The workflow name is on the left and the run controls are on the right.

![A workflow open, with the run bar at the top and the results bar at the bottom](/media/en/interface.webp)

| Control | What it does |
|---|---|
| **Real API** / **Simulation** | Where the cases run. **Real API** sends the requests to the base URLs of the active environment. **Simulation** answers from the contract, with no network calls. See [Simulation](/test/simulation/). |
| **Run** | Runs the selected cases that are ready. Its label says how many: **Run 3 cases**, **Run 1 case**. With none ready it says **Run** and cannot be pressed. |

![The run bar of Pokemon card: Real API or Simulation, and Run 3 cases](/media/en/test-runbar.webp)

The environment is not in the run bar. The active one is always visible at the top right of the window, in the left half of the pill, the one with the database icon: the collection environment, in its color, or in Luvin green without one. It is the one whose base URLs, variables and credentials are used. Click that half to switch. **Configure environment…**, at the end of its list, opens it. The right half, with a globe, is the global environment. See [Environments](/environments/overview/).

Before you press **Run**, the line at the top of the **Cases** tab says what will happen: how many cases are selected, how many go against the real API, how many are simulated and how many will not run. See [Cases](/test/cases/#the-cases-tab).

## Run the cases

<Steps>
1. Open the workflow.
2. In the **Cases** tab, tick the cases you want. See [Cases](/test/cases/).
3. In the run bar, choose **Real API** or **Simulation**.
4. Check the environment at the top right of the window, in the left half of the pill. Click it to choose another one.
5. Press **Run**. You can also press ⌘ + Enter on macOS, or Ctrl + Enter on Windows.
</Steps>

The results open at the bottom. While the run is in progress they show which case is running, for example *Running case 2 of 5*, and each case gets its verdict as it ends.

In the **Design** tab the results do not open at the bottom: the canvas switches to **Run** and shows the result on each step, with a result bar over the canvas. **Results ▴**, in that bar, opens the full results. See [Results on the canvas](/test/run-on-canvas/).

## Run one case

<Steps>
1. In the **Cases** tab, find the case.
2. Press ▶ on its row. Its tooltip says **Run only this case**.
</Steps>

The case runs even if it is not ticked. The results then show that case only. If ▶ cannot be pressed, the case cannot run: rest the pointer on the button to read why.

<Aside type="caution">
▶ starts at once. It does not show the confirmation for steps that modify data, described below.
</Aside>

## Steps that modify data

A step that uses `POST`, `PUT`, `PATCH` or `DELETE` creates, changes or deletes data. When a case goes against the real API and the workflow has such steps, **Run** first shows a notice: *These steps modify data in the "…" environment*, with the method and URL of each step.

| Button | What it does |
|---|---|
| **Run anyway** | Runs the cases. Luvin does not ask again until you switch environment or change a base URL. |
| **Use simulation** | Switches to **Simulation** and runs there. Nothing is sent to the API. |
| **Cancel** | Closes the notice without running. |

![The notice before running PayPal's Create order against the real API: a POST modifies data in the Sandbox environment](/media/en/test-run-confirm.webp)

Read the environment name in the notice before you confirm.

## Other notices before a run

- *Credentials are missing in "…": calls that need them will answer 401.* **Fill in** opens the environment.
- *This workflow signs in with OAuth 2.0 to: …* Press **Sign in**, or press **Run** and the sign-in opens first. If you cancel it, the workflow does not run. See [OAuth 2.0](/authorization/oauth2/).
- *N messaging step(s) are simulated*, next to the workflow name. Messaging steps are simulated even against the real API. See [Simulation](/test/simulation/).

## Run part of a workflow, or one route

On the canvas of the **Design** tab you can run less than the whole workflow:

| To… | Use | See |
|---|---|---|
| Stop before a step, change what it receives and continue | **⏸ Pause here**, or **F9** | [Debug a workflow](/test/debug/) |
| Run one step, up to a step or from a step | **▷ Run only this step**, **▷ Run up to here**, **Run from this step** | [Debug a workflow](/test/debug/#run-only-up-to-or-from-a-step) |
| Go through one route with a simulated response | **▷ Probe**, on the route | [Probe routes and coverage](/test/probe-routes/) |

## Stop a run

While cases are running, the **Run** button becomes **Cancel**. The results show a **Cancel** button too. The run stops at the current step, and the cases that had not started stay **Pending**. If the run is paused before a step, the pause closes.

## Run every workflow of a file

To run all the workflows of an Arazzo file one after another, open the file in the sidebar and press **▶ Run all**. See [The Arazzo file](/design/arazzo-file/).

## Run several workflows, several times

To choose which workflows run and in what order, repeat them in several iterations, or give each iteration its own data from a CSV or JSON file, use the **Runner**: open the **⋯** menu of an Arazzo file in the sidebar and choose **Run workflows (runner)**. The Runner never stops to ask you to choose from a list. See [Run workflows](/runner/workflows/).

## When a workflow depends on another

Some workflows need another one to run first: for example, **Battle matchup** in the Pokédex runs after **Type explorer** and uses its outputs.

- The workflows it depends on run first, in order, once per run, before the cases.
- Each one uses its own default values, from its own **Inputs** tab.
- In **Simulation** they are simulated too.
- The results show them under **Preparation**. Click one to see its steps.
- If one of them fails, the cases cannot be tested. Each case ends as **Inconclusive** and says which workflow failed.

![Battle matchup in simulation: Type explorer ran first under Preparation, then the happy path](/media/en/test-preparation.webp)

See [Dependencies](/design/dependencies/) and the recipe [One workflow logs in, others reuse its token](/recipes/depends-on/).
