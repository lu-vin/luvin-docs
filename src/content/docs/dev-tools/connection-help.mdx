When a run against the **Real API** gets no answer from the API, Luvin shows a panel called **Could not reach the API**. It tells you what to check and what you can do next. You do not have to open it: it appears by itself above the results.

## When it appears

The panel appears when a step could not connect: the server did not answer, the address does not exist, or your computer cannot reach it. It does not appear when the API answers with an error such as 401 or 500. Those are results, and you read them in the [results](/test/results/).

The first line says how many cases are affected and which servers did not answer:

```text
3 case(s) got no response from https://api.shop.test. It is usually one of these:
```

Click **×** (**Close**) to hide the panel.

![The "Could not reach the API" panel, with the link to open the address and the buttons to try in simulation or review the environment](/media/en/connection-help.webp)

## What it checks

### Is the URL right and the server up?

Open the address: if it does not load, the problem is not Luvin. The panel gives one link per server, **Open https://api.shop.test ↗**. If the address is wrong, fix it in the environment (see below).

## What you can do from the panel

| Button | What it does |
|---|---|
| **Try in simulation** | Runs this workflow again in **Simulation**, with no network. Use it to keep working while the API is fixed. |
| **Review environment** | Opens the active environment, to check the base URL. |

At the bottom, the panel reminds you that you can copy a step as cURL and try it in your terminal, to see the raw error. See [Network](/dev-tools/network/).

<Aside type="tip">
If the API is only reachable through a proxy or asks for a client certificate, set them in [Preferences → Network](/get-started/network/).
</Aside>
